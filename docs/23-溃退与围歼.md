# 23 溃退与围歼：伤亡为什么不对称

> 这一轮改的全是 **Systems（引擎侧）**，一个字没动内容数据。
> 起因是上一轮留下的那个诚实遗留：伤亡 29.2 对 28.5，几乎对称——
> 而武汉会战中方伤亡约为日军的 3–4 倍。差距不在对射，在**崩了之后**。

---

## 1 三个连起来的引擎 bug

### 1.1 攻方永远进不了守方的省（战线第 5 天冻结）

`STACK_LIMIT = 3` 原来是"一个省最多 3 个地面单位，**不分敌我**"。
于是守方在每个前线省摆满 3 个师，攻方就永远进不来，战斗也就永远不会发生。
一个 35 公里宽的省，双方各驻几个师相持，才是战场常态。

改成**按方计位**：每方各限 3 个，一个省最多 3 守 + 3 攻。

### 1.2 进攻方绕开敌军去涂空省（60 天一场陆战都没打）

AI 挑目标是"按兵力估计最小"，而空省永远是 0，于是日军一路绕过国军
去占空地。现在 `pick_target`：**先打有敌人的省，没有敌人才去占空省**。
进攻方的目标是对方的部队，不是地图上的颜色。

另外，没侦察到的敌军估计值是 0——不能拿 0 当"这里没人"。现在按
"至少一个师"折算，逼进攻方先把侦察做完再下手。

### 1.3 士气不会因为"打不过"而崩

以前士气只随自己的伤亡抖一点，火力被压制的部队**永远不会崩**，
于是永远不会溃退。现在每 tick 多一项**压制冲击**：
`(敌我火力比 − 1) × 8%`，上限 6%/日。

## 2 溃退与围歼（新系统）

士气 < **0.25** 且当面**打不赢**（敌战力 > 我战力）→ 溃退：

1. 退向邻接的己方空省（挤也要去）；
2. 己方没有可退的，就退向**任何没有敌军的邻省**（溃兵往乡下跑）；
3. 四面都是敌军 → **被围歼**，走统一覆灭结算（将领结局、整编资格都在里面）。

每次溃退丢 **6%** 兵力（丢辎重、掉队、被追）。

> 第 2 条是必须的。第一版只认"己方省份"，于是进攻方在敌境崩溃时
> 背后没有自己的旗子，每个师团都判"无路可退 → 围歼"——
> 实测日军 60 天从 96.5 千打到 **9.5 千**。
> 围歼应当是"四面都是敌人"，不是"前后没有自己的旗子"。

## 3 数值

| 项 | 值 | 理由 |
|---|---|---|
| 溃退阈值 | 士气 0.25 | 低于此已不成建制 |
| 溃退损失 | 6% | 丢辎重、掉队、被追 |
| 压制冲击 | `(比−1)×8%`，上限 6%/日 | 知道自己打不过，泄气 |
| 战斗强度 | 2.5%/日 | 原 6% 在"天天都在打"下 60 天能把双方一起磨光 |

## 4 结果（77 天无头跑批）

```
tick 77 | 国军 88.5 千 守 62 省 | 日军 34.6 千 占 25 省 | 存活 18
```

改动前：`国军 116.1 / 日军 61.2`，战线从第 5 天起一动不动，双方只是被
非战斗减员磨死——**一场没人开火的战役**。

现在：日军在推（占 25 省），但**打得很贵**（从 96.5 千掉到 34.6 千），
国军守住了大半（62 省），18 个番号全部还在（没有整建制蒸发）。

日军比国军损失比例更大，原因是结构性的：进攻方要进敌省（补给只剩就地征发
0.5）、要打有地形与工事加成的守军、国军还有南浔铁路的补给加成。
这就是"人多却打得苦"的另一面。

## 5 测试

`crates/sim-core/tests/rout.rs` 4 个：

1. 崩了 → 退向后方空省、丢兵、有战报、交还 AI；
2. 四面皆敌 → 被围歼（将领结局照常结算）；
3. 士气低但没交火 → 不溃退；
4. 溃退确定性（同种子同历史）。

外加修正两条既有测试与一个断言：
- `golden_replay` 的"国军至少留一个省"改成"日军占到过省"——
  加上溃退之后，八省直线场景被推平是合法结局，不是 bug；
- `rout.rs` 的围歼用例要在唯一退路上驻一支敌军，否则溃兵会逃进
  敌军控制但没有敌军的省（这正是第 2 条放松后的正确行为）。
