# 22 结局与整补：这一局怎么收场

> 没有结局，打到第 78 天游戏就静静卡住。没有整补，77 天打完所有部队都是空架子——
> 而且**永远恢复不了**。两件事都补上了。

---

## 1 结局：不判胜负，只判"这是个什么局面"

设计原则（`docs/05`）不变：**不给一个字**。淞沪打完，中国丢了上海，
但"以空间换时间"实现了——这算赢还是输？所以只做一件事：

> **战役结束时，按一组可读的指标挑一条结局。**

引擎只提供句式，**内容决定"什么算苦撑"**：

```json
{
  "id": "E2", "name": "以空间换时间", "priority": 20,
  "text": "放弃了几座城，主力还在……",
  "require": [
    { "metric": "day", "cmp": "ge", "value": 77 },
    { "metric": "provinces", "side": "cn", "cmp": "ge", "value": 40 },
    { "metric": "units_alive", "side": "cn", "cmp": "ge", "value": 9 }
  ]
}
```

指标：`day` / `provinces` / `strength` / `losses` / `units_alive` /
`commanders_lost` / `holds_province`。按 `priority` 从小到大判，
第一个全部满足的就是它。`at_end_only: false` 允许提前触发（速溃、崩盘）。

本模块写了 6 条：

| id | 名字 | 条件 |
|---|---|---|
| E5 | 两败俱伤 | 期满 · 守 45 省以上 · 伤亡 ≥30 千 |
| E2 | 以空间换时间 | 期满 · 守 40 省以上 · 9 个番号以上存活 |
| E3 | 苦撑 | 期满 · 守 35 省以上 |
| E4 | 僵持 | 期满（兜底） |
| E7 | 速溃 | 随时 · 守 ≤20 省 |
| E6 | 中枢崩解 | 随时 · 存活番号 ≤4 |

实测（`IRONMIND_LLM=mock`，一路 `advance` 到底）：**E2 以空间换时间，第 77 日**，
国军守 59 省、伤亡 18.8 千、尚存 9 个番号。

## 2 "推进到有事"：跳过没事的日子

玩家真正想要的不是"再推一天"，是"**跳过没事的日子**"。
`POST /api/advance` 一直推到以下任一发生（上限 30 日）：

- 出现**要紧的**战报（战斗 / 易手 / 抗命 / 将领 / 编制 / 断粮）
- 番号有增减
- 判出结局

> 规则类战报（山地行军减员）不算"有事"——它每 tick 每个单位一条，
> 算进去的话 `advance` 就退化成逐日推进了（已踩过）。
> 界面上是「推进到有事 ⏎」。

## 3 整补：补人，不只是歇气

`Rest` 以前只回士气和补给，兵力**只减不增**。于是打到后期所有部队都是残废，
而且永远恢复不了——"守住了"的部队第二天依旧是一千人的空架子。

现在：补给 > 0.5 时，每天补满编的 **0.4%**。一支 12 千的军从 6 千补到 9 千
要 60 天左右——够慢，不会让"打残"这件事变得无所谓；但它给了你**选择**：
把部队拉下来整补，还是硬顶着打。

补给不足就补不进人（测试盯住这一点）。

## 4 踩到的坑：一条子句写错，整条结局永远成立

第一次跑，第 1 日就判出"速溃"。原因：内容里把 `cmp: "le"` 写成了 `"lte"`，
加载器把这条**子句**丢掉，于是 `require` 变成空数组，
`all()` 对空集合恒为真——**结局立刻命中**。

修法两层：
1. 加载器：任一条子句读不懂，就丢掉**整条结局**（不是只丢子句），并打警告；
2. 空子句的结局直接跳过。

这个坑很值得记：条件系统里"少一条约束"= "条件变松"，
和"多一条约束"完全不是同一类错误，而且不会报错。

## 5 测试（`crates/sim-core/tests/ending.rs`，6 个）

1. 到日子判出名字正确的结局，且带关键数字；
2. 没有命中的规则时给兜底结局（E0），不让战役无声卡住；
3. `at_end_only: false` 的结局能当天触发；
4. `at_end_only: true` 的结局中途不触发；
5. 整补十天兵力上升但补不满；
6. 没有补给的整补只涨士气，不补兵。

## 6 没做

- **历史基线对照**（`docs/05` §6）：结局面板里应当有"史实是……"一行。
  这需要把史实数据写进模块，属于内容工作。
- **结局后的复盘**：命令流回放 + 关键时刻标记。
- **派系与人事**（`docs/03`）：`commanders_lost` 现在只是计数，
  结局里说不出"谁死了"，因为没记录名单。将领名单要单开一张表。
