# 26 · 模块作者指南：写给将领的 AI 提示词

这一篇只讲一件事：**模块里的 `persona` / `agenda` / `objectives` 该怎么写。**

引擎不写任何历史。将领的性格、脾气、说话方式全在模块数据里，模块作者写错方向，
引擎只会忠实地把一个错的人演给你看。下面这些结论是踩出来的，不是推出来的。

---

## 一、哪些字段会进提示词

| 字段 | 位置 | 进哪个提示词 | 作用 |
|---|---|---|---|
| `title` | `units[].commander.title` | 问策 + 军情 | 职务，决定他开口的身份 |
| `persona` | `units[].commander.persona` | 问策 + 军情 | 出身、经历、**用兵习惯** |
| `agenda` | `units[].commander.agenda` | 问策 + 军情 | **他在意什么**（下一篇详说） |
| `obedience` / `initiative` / `aggression` / `caution` | 同上 | 问策 + 军情 | 0–1 数字，作为"性格数字"直接给模型 |
| `sides[].hq.name/title/persona/agenda/objectives` | `module.json` | 统帅部提示词 | 只有**敌方**统帅部会由 AI 驱动 |
| `name` / `strength` / `position` / 省情 | — | 自动注入 | 不用你写 |

代码位置：

- `crates/sim-server/src/llm.rs`
  - `SYSTEM` + `build_user()` —— **问策**（"这个命令你听不听"）
  - `SYSTEM_SITREP` + `build_sitrep_user()` —— **军情**（"报一报你看到什么"）
  - `build_hq_*` —— 统帅部

这些字段**只进提示词，不进模拟**。改它们不动数值、不动状态哈希、不影响回放与旧存档，
只影响模型怎么演这个人。所以放心改、大胆改。

---

## 二、`persona` 写什么：他怎么打

写**出身、阅历、用兵习惯**。这些是模型的"手"，决定他给出来的动作长得什么样。

```json
"persona": "熊本出身。第6师团是日军最老的师团之一，从甲午一路打下来，兵骄将悍。
            他骑兵出身，习惯绕侧翼，看不上正面硬顶。"
```

判据：**读完这段，你能预判他会怎么打一场仗。** 能，就对了。

反面：写一堆生平、师承、爱好，但读不出"他会怎么用兵"——那只是简历。

---

## 三、`agenda` 写什么：他怎么报

这是最容易写错的一栏。

### 不要写「他为什么不肯打」

下面这些是从真实模块里抓出来的旧文案：

```
"不能折在二流战场上，但也不能让别人抢了头功"
"不愿为一次冒进把师团打残"
"一个联队打光，编成就要撤，他的军旅也就完了"
"若被当消耗品用，他一定会有话"
"不想替中央军去填最深的坑"
"打光就没了，所以一直想找便宜打"
```

**这些在史实上是错的。** 保存实力、怕部队打光、不愿替友军填坑——那是**军阀政治**的逻辑，
发生在全国层面：军头怕被中央吞并、怕失掉本钱。它不属于一场具体战役的战术尺度。

抗战正面战场上，**全连殉国是常态**。没有一个师团长会把「我部队会打光」当理由递上去，
递上去也没人会准。你把这条写进 `agenda`，模型就会照着演一个不肯打仗的人，
而玩家的命令会被顶回来——那不是"真实"，那是机制坏了。

### 要写：他怎么打、怎么报、报得准不准

`agenda` 的正确用途是**执行风格 + 报告偏差**。分成三块想：

**1. 报功的口径**
- 战果往大里报，还是照实报？
- 伤亡缩不缩水？
- 会不会把"先头到了"写成"已到达"？

```
"他要第6师团报上去的战果永远比友军大一截。"
"他把部队压在最先头，伤亡写得最轻——「未遇有力抵抗」是他的口头禅。"
"话最少，报告也最短：打下来报「已克」，打不下来一个字不写，等上面来问。"
```

**2. 投入的脾气**
- 一次压上，还是逐次投入、留预备队？

```
"打的时候宁可多花一天把侧翼绕开，也不肯正面硬顶。"
"他抢功最急，也最敢把部队往深山里塞。"
```

**3. 敌情的滤镜**
- 好战的人倾向**低估**当面之敌，催着打。
- 谨慎的人倾向**高估**，先说要准备什么。
- 主动性低的人**报得旧**：把前两天的印象当成现在的。

```
"他习惯把当面敌情算得比实际更细，可一旦纸面和实地对不上，他信纸面。"
"他熟地形，报敌情总附带自己的判断，往往准；只是那判断里永远有一条：路和粮在哪里。"
```

这一块是**这套系统最有意思的地方**：同一个省，两个军长给你两份互相矛盾的敌情，
该信谁是玩家的活。所以别把所有人写成同一个调子——好战的和谨慎的必须给出**相反**的偏差。

### 长度与语气

- **一句话，30–60 字。** 太长会稀释模型的注意力。
- **第三人称陈述**（"他要…""他信…"）。别写成第一人称独白。
- 写**具体行为**，不写形容词堆砌。"宁可多花一天把侧翼绕开" > "用兵谨慎"。

---

## 四、数字与文案要一致

`obedience / initiative / aggression / caution` 是给模型的"性格数字"，
`persona` 和 `agenda` 是同一个人的文字版。**两套不能打架。**

| 数字 | 高 | 低 |
|---|---|---|
| `aggression` | 愿意用损失换时间与战果，报告里低估敌人 | 先算代价，报告里高估敌人 |
| `caution` | 先把退路和阵地算清楚再动手 | 敢冒险、敢往侧后钻 |
| `initiative` | 主张自己选方向，会说清私下已动了什么手脚 | 按令办事，报告四平八稳 |
| `obedience` | 基本不顶撞，最多在报告里嘀咕 | 会争辩、会按自己的打法打折 |

写 `aggression: 0.4` 却说"他性好冒险、敢把部队往深山里带"，模型会精神分裂。

## 五、两条通道的区别（作者须知）

| | 问策（`SYSTEM`） | 军情（`SYSTEM_SITREP`） |
|---|---|---|
| 什么时候问 | 「委诸将领」模式，每 tick 问一次 | 「亲自指挥」模式，每天最多问三支在接触中的部队 |
| 问什么 | 上级这道命令，你听不听、怎么执行 | 你看到什么、你打算怎么办 |
| 答什么 | **JSON**（动作 + 目标 + 理由 + 回电） | **一段散文**（120 字内），直接进战报 |
| 会不会产生命令 | 会 | **不会**，只进战报 |

所以 `agenda` 里写的"报告口径"在两条通道里都会生效，而"打法脾气"主要在问策里起作用。

---

## 六、统帅部（`hq`）不一样

`sides[].hq` 写的是**作战方针**，不是脾气：

```json
"persona": "情报参谋出身……用兵讲章法，喜欢先集中兵力于一点再扩张战果。",
"agenda": "他的目标是把南浔线打通、相机拿下南昌。",
"objectives": [
  "沿南浔铁路南下，夺取德安，打开通往南昌的门户",
  "保护长江水路补给线，沿岸据点不得失守"
]
```

`objectives` 是**条目化的目标**，模型会照着排优先级。写方针、写优先级，不要写成"我怕被各个击破"
——同样是那条线：**别把保存实力写进动机**。玩家亲自指挥时，这一层不由 AI 驱动（玩家本人就是统帅部）。

---

## 七、改完怎么验

1. **别改哈希**：这些字段不参与模拟，改完 `cargo test --workspace` 应当仍然全过。
2. **看两个人给不给出不同的话**：挑两个性格相反的将领，让同一支部队处于同一处境，
   分别在「亲自指挥」下推进两天，去「要闻」看军情——如果两段话的敌情估计**方向相反**，就对了。
3. **看有没有"不肯打"**：如果报告或回电里出现「职部兵力不足，恳请体恤」「恐本部折损过大」，
   那是 `agenda` 写偏了，回去改成执行风格。

## 附：一份改好的对照

| | 旧（动机错误） | 新（执行风格 + 报告口径） |
|---|---|---|
| 精锐师团长 | 不能折在二流战场上 | 报战果永远比友军大一截；宁可多花一天绕侧翼，也不正面硬顶 |
| 条令派 | 不愿为一次冒进把师团打残 | 报伤亡从不缩水，报进度却爱用「大致」 |
| 特设师团长 | 一个联队打光，编成就要撤 | 报告总晚半天，一定先报侧后威胁；夜间把伤亡写得比白天重 |
| 地方军 | 不想替中央军填最深的坑 | 话最少：打下来报「已克」，打不下来一字不写 |
| 临时配属 | 打光就没了，所以总想找便宜打 | 看见便宜就扑上去；只写缴获和俘虏，不提自己已偏离命令 |

同一个人的性格没变，变的是**他因此怎么说话**，而不是**他因此不干活**。
