# 24 · 桌面版：从"能跑"到"能装"

前面二十几篇讲的都是**这场战争怎么模拟**。这一篇讲的是另一件事：
怎么让一个不懂 Rust、不会开终端的人，**双击一个图标就能玩**。

这两件事没有关系，所以放在最后单独说——引擎的规则一行没改，
只是多了一个窗口外壳和一个首页。

---

## 1. 为什么需要这一层

在这之前，跑起来是这样的：

```powershell
$env:IRONMIND_MODULES = "F:\dsh\nanxun-1938"
cargo run -p sim-server
# 然后自己去浏览器打开 http://127.0.0.1:8899
```

对开发者这没问题。对玩家这就是**不可发布**：

| 问题 | 后果 |
|---|---|
| 要装 Rust、要编译 | 99% 的人走不到第二步 |
| 要开浏览器、输地址 | 看起来像个网页工具，不像游戏 |
| 端口写死 8899 | 同时开两局会撞在一起 |
| 没有入口页 | 一进来是张没名字的地图，不知道下一步干什么 |
| 没有引导 | 这个游戏的规则和别人不一样（不能直接动部队），不教就是劝退 |
| 存档靠 `prompt()` | 那个浏览器弹窗一眼就被看穿"这其实是个网页" |

桌面版要解决的就是这六条。

---

## 2. 结构：多了一个 `sim-desktop`，别的一层没动

```
┌──────────────────────────────────────────┐
│ IronMind.exe        (crates/sim-desktop) │  ← 原生窗口 + 拉起内核
│   ├─ WebView2 窗口                        │
│   └─ 子进程：sim-server.exe --port <随机> │
└──────────────────────────────────────────┘
                    │ localhost HTTP
┌──────────────────────────────────────────┐
│ sim-server (内核 + 页面)                  │
│   sim-core / sim-content                  │
└──────────────────────────────────────────┘
```

**外壳不含任何战役逻辑**，它只做四件事：

1. 找一个空闲端口（不跟开发时的 8899 抢）；
2. 把 `sim-server` 作为子进程拉起来，**关窗就杀掉**，不留后台进程；
3. 等内核就绪（最多 25 秒）再开窗口，避免玩家看到一片错误页；
4. 读安装目录的 `settings.env`，作为子进程的环境变量。

窗口用 `tao` + `wry`（WebView2）。为什么不自己画 UI：
地图是 SVG、面板是 DOM，这套东西在 Web 里已经写完了，
换成原生绘制等于把二十几篇文档里的界面全部重写一遍。

## 3. 装成什么样

```powershell
pwsh -File install.ps1                    # 编译 + 安装 + 建快捷方式
pwsh -File install.ps1 -Uninstall         # 卸载（存档会先备份）
```

装完是这样一个目录（**不需要管理员**，全在 `%LOCALAPPDATA%`）：

```
%LOCALAPPDATA%\IronMind\
  IronMind.exe                    外壳
  sim-server.exe                  内核
  ironmind.ico                    图标
  modules\                        模块（换战役不用重新编译）
    demo_1805.imod\
    siege_tianjiazhen.imod\
    nanxun_1938.imod\
  settings.env                    配置（记事本可改）
  saves\                          存档（命令流）
  logs\desktop.log                外壳 + 内核的日志
  IronMind.exe.WebView2\          浏览器运行时数据（含引导是否看过）
```

装完会有：

- 开始菜单 →「钢心」
- 桌面 →「钢心」
- 设置 → 应用 → 已安装的应用 →「钢心」（可卸载）

`install.ps1` 的参数：

| 参数 | 说明 |
|---|---|
| `-Dir` | 装到别处 |
| `-Modules` | 额外要装进去的模块目录（可多个） |
| `-DefaultModule` | 第一次打开时先加载哪个战役（名字或全路径） |
| `-SkipBuild` | 直接用 `target\release` 里现成的产物 |
| `-NoShortcuts` | 不建快捷方式 |
| `-Uninstall` | 卸载 |

## 4. `settings.env`：给"只会双击图标的人"一条配置通路

玩家的桌面上没有环境变量面板，但有记事本。

```ini
# 一行一个 KEY=VALUE，# 开头是注释
# IRONMIND_LLM=off
# IRONMIND_API_KEY=sk-................
# IRONMIND_MODEL=deepseek-chat
# IRONMIND_API_BASE=https://api.deepseek.com/v1
# IRONMIND_HQ_INTERVAL=2
# IRONMIND_MODULES=D:\my-modules
```

**优先级：系统环境变量 > `settings.env` > 程序默认。**

方向是刻意的：命令行上临时调试时，不能被文件里的旧值盖掉。
外壳只把**键名**写进日志，值（可能是 API key）绝不落盘到日志里。

默认不联网：没填 API key 时，将领大脑走本地模拟判断，
规则、地形、战斗、结局全都正常——只是将领的"脑子"简单一些。

## 4.5 首次设置：装完第一次就问

`settings.env` 只是**存储**，不是**入口**。让双击图标的人"去改一个文本文件再重启"，
等于这件事没做完。所以第一次启动会直接弹一个设置页：

```
首次设置 / 接入将领大脑
  ├─ 用本地规则判断（不联网·免费）   [就这样开始]
  └─ 接入模型（推荐）
       API 地址 [https://api.deepseek.com/v1]
       模型     [deepseek-chat]
       密钥     [sk-...]                [测试连接] [保存并开始]
```

几个刻意的选择：

| 决定 | 原因 |
|---|---|
| **两条路都能走**，不强制要 key | 没有 key 也能玩是承诺过的；强制联网会把一半人挡在门外 |
| 有「测试连接」 | 填错了要当场知道，而不是推到第 3 天才在战报里发现将领不说话 |
| 保存后**立刻生效**，不用重启 | 配置放在 `Arc<Mutex<Config>>` 里，后台线程每一单重新取一次 |
| 记住了就不再弹 | `IRONMIND_SETUP=done` 写进 `settings.env`；之后要改走「设置 → 接入模型…」 |
| 密钥**不回传**前端 | `/api/llm` 只给 `has_key`。重开设置页时输入框是空的，留空 = 沿用已存的 |
| 只写 `settings.env`，不碰别处 | 文件仍然是唯一事实；接口只是它的编辑器，注释和别的键都保留 |

`POST /api/settings`（写文件 + 热生效）与 `POST /api/settings/test`（真打一次模型）
都只监听 127.0.0.1。`mode` 只接受 `model` / `local`，别的值直接 400——
"悄悄当成本地"和"悄悄当成驳回"是同一种错误。

## 5. 首页

启动即显示，**不等内核**。引擎没好时按钮是灰的、状态栏写"连接中"，
而不是让玩家盯着一块黑屏。

| 项 | 说明 |
|---|---|
| 继续 | 读最近的一份存档；没有存档时这一项是灰的，主角换成"新的战役" |
| 新的战役 | 列出所有模块：名字、规模、版本、扮演哪一边、这段战史在讲什么 |
| 读取存档 | 列出槽位（第几日 / 几条命令 / 时间），点一下就读 |
| 上手引导 | 六步，随时可以重看 |
| 设置 | 将领大脑状态、模型、会商间隔、模块目录、存档目录、最近的模型错误；**接入模型…** 重新打开首次设置 |
| 关于 | 这个引擎坚持什么、不做什么 |

右侧的**战役卡**显示当前模块：名字、规模、描述、第几日、我军兵力、敌军估计。

> 敌军估计写"未查明"而不是"约 0.0 千"。
> 情报是情报，事实是事实——一点没侦察到时写 0，等于骗玩家说敌人不存在。

顶栏的国名/战区名也是从模块读的。之前那两个字是写死在 HTML 里的，
换一场战役左上角还挂着上一场仗的番号——那是引擎越界了。

## 6. 引导：只讲"和别人不一样的地方"

这个游戏有三件事反直觉，不说清楚就是劝退：

1. **你不能拖动部队。** 唯一的指挥手段是电报，一句话说清意图。
2. **将领有独立判断。** 会追问，会抗命，抗命的结果也会进战报。
3. **没有"你赢了"。** 战役结束给出的是一条结局和它的依据。

所以引导只有六步，每一步都指着一个真实存在的控件（地图、电报台、
公文堆、推进按钮、战报信箱），最后一步回到这三条原则：

| 步 | 目标 | 讲什么 |
|---|---|---|
| 1 | 地图 | 地形是真的：高程、河网、铁路来自模块 |
| 2 | 电报台 | 唯一的下令方式；收报人可以细到师 |
| 3 | 公文堆 | 请示要你批，抗命不会悄悄消失 |
| 4 | 推进 1 日 | 空格 = 一天，回车 = 推进到有事；时间最贵 |
| 5 | 战报信箱 | 战报会迟到，所以要预判而不是反应 |
| 6 | —— | 没有胜负，只有结局 |

实现上是一个 3 像素的洞 + `box-shadow: 0 0 0 9999px` 当遮罩：
**被高亮的东西仍然可点**，因为它只是没被遮住，不是被盖住了。
卡片位置按"右边有地方就放右边，否则左边，否则翻到上面"算——
底栏那几个按钮就在屏幕最下沿，卡片必须往上翻，不然正好盖住要高亮的东西。

跳过也算看过（`localStorage.im_onboarded`），之后不再打扰。
重看走首页的"上手引导"。

## 7. 存档、日志、诊断

- 存档：`saves\*.json`，存**命令流**不是世界快照；读档重跑并核对哈希。
- **自动存档**：每 5 天写一份 `saves\auto.json`，固定槽位，不会挤掉手工存档。
  首页"继续"取的是**按修改时间最新**的一份，所以自动存档也能接着玩。
  （加这个是因为：有人推了 39 天、一次没存，切战役的时候整局没了。）
- 日志：`logs\desktop.log`，外壳和内核写同一份（`[desktop]` 是外壳的行）；
  `logs\server.log` 是内核的请求与判断流水。
- 报 bug 时最有用的三样：`logs\desktop.log`、`settings.env`、首页"关于"里
  显示的版本号（`/api/version` 从 `CARGO_PKG_VERSION` 取，不会和代码脱节）。

### 没有 API key 也能玩

`settings.env` 里不填 key，将领仍然会**下达命令**——用内核里的本地规则判断
（`mock_judgement` / `mock_hq`）：认电报里点的地名、按兵力与将领性格选
进攻/固守/筑工事/撤退，也会在有理由的时候请示甚至抗命。
区别只是"脑子"简单：它不会像模型那样读懂含糊的话。

界面上会如实写"规则 AI（本地判断，未接模型）"，不会让人以为模型在思考。

## 7.5 一局真实对局的日志长什么样

玩过一局之后 `logs\server.log` 里应该能看到这几行——**缺哪一行就说明哪一环断了**：

```
发电报 #1 → 第18军，第 1 日送达（1 日后）        ← 电报在途
电报 #1 送达 第18军（1 个单位收到）               ← 进指挥链
第18军（黄维）：上意指向万家岭…〔请示 #6：请裁示是否准他改令〕  ← 将领判断
自动存档 saves/auto.json（第 5 日，4 条命令）      ← 自动存档
```

如果只看到"发电报"而没有"送达"，就是模型/规则这一层没跑起来。
这条检查写在这里，是因为**曾经**没有 API key 时电报会被静默丢弃：
界面上只是"发了电报送出去了"，既没有回电也没有任何报错。

## 7.8 macOS：同一个外壳，只是包装不一样

`crates/sim-desktop` 本来就是跨平台的（`tao` + `wry`），Windows 上 wry 用
**WebView2**，macOS 上就是系统的 **WKWebView**。所以"移植到 Mac"没有新写壳，
只补了三件事：

| 文件 | 干的活 |
|---|---|
| `tools/build-mac.sh` | 装配 `IronMind.app`：两个二进制进 `Contents/MacOS`、演示模块进 `Contents/Resources/modules`、`AppIcon.icns`（复用 iOS 那套 1024 图，`iconutil` 转）、Info.plist、ad-hoc 签名、打 zip |
| `crates/sim-desktop/src/main.rs` | 加 `mac_data_root()`：没有便携布局时数据落 `~/Library/Application Support/IronMind` |
| Info.plist（脚本里生成） | `NSAllowsLocalNetworking`（不开就白屏，和 iOS 同一个坑）、声明 `org.ironmind.imod` 文档类型 |

**为什么存档不能放在 `.app` 里**：写进 bundle 会破坏代码签名；从只读卷、网盘、
`/Applications` 只读挂载启动时更是直接失败。Windows 那套"exe 旁边的
`modules/`、`saves/`"是便携版思路，macOS 按系统惯例走 Application Support。
Windows 的便携布局**一行没动**（`mac_data_root` 是 `#[cfg(target_os = "macos")]`）。

```bash
tools/build-mac.sh            # → dist/IronMind.app + dist/IronMind-<版本>-mac.zip
open dist/IronMind.app
```

签的是 **ad-hoc**（`codesign -s -`）：本机双击能跑。分发给别人要开发者证书 + 公证
—— 和 iOS 那个未签名 ipa 一样，那一步不归这个项目做。

**端口**：首选 18735（iOS 那个壳是 18731，两个平台版本可能装在同一台机器上）。
固定端口不是为了好看——页面按 `http://127.0.0.1:<port>` 区分 origin，端口一变
`localStorage` 就是另一份，"看过引导"这类标记每次启动都会丢，引导于是每次都自己弹。
被占了才退到系统分配。

**wry 不实现 JS 对话框**：`alert()` 无声、`confirm()` 恒为 false（Windows 的 WebView2
自带默认对话框，所以那边看不出来）。所以页面里一律用自绘的 `Dlg`——
这也是项目原来的方向（`prompt()` 早就换掉了）。**别在新代码里用 `confirm()`。**

**已知的毛病**：模块导入的文件面板里，选好文件后点「打开」没反应，**双击文件可以**。
wry 是用 `NSOpenPanel.runModal()` 弹的，非激活窗口下「打开」那一下会被吃掉。
绕法两条：双击文件；或者干脆把 `.imod` 放进
`~/Library/Application Support/IronMind/modules/`（引擎每次列模块都扫这个目录）。

## 8. 已知限制（写下来比藏起来好）

| 限制 | 说明 |
|---|---|
| 需要 WebView2 | Win11 和新版 Win10 自带；老系统要装一次微软的 Evergreen 运行时 |
| 没有代码签名 | 首次运行可能有 SmartScreen 提示（点"更多信息 → 仍要运行"） |
| 设置部分能在线改 | 模型地址/模型名/密钥/本地模式可以；会商间隔、模块目录还得改 `settings.env` 再重启 |
| 没有自动更新 | 重跑一次 `install.ps1` 就是更新 |
| 单实例没做 | 同时开两个会各起一个内核；存档目录共享，可能互相覆盖 |
| exe 本身没嵌图标 | 快捷方式有图标（指向 `.ico`），资源段里的图标还没做（要 `rc.exe`） |
| 端口随机 | 好处是不撞车；代价是没法用固定地址访问（要固定就命令行传 `--port`） |
| 规则 AI 比较吵 | 没接模型时，一个方向上的军、师常在同一天各自请示，公文堆会堆起来；接下模型后判断更集中 |

## 9. 验证方法

界面改动不能靠"看起来没问题"——已经被缓存的旧页面骗过两次。都走无头：

```powershell
# 首页
node tools/shot.js --url http://127.0.0.1:8899/ --out tools/_shots/home.png --wait 2200
# 引导第 N 步
node tools/shot.js --url http://127.0.0.1:8899/ --out tools/_shots/g2.png --wait 2200 `
  --eval "(async()=>{Home.hide();await new Promise(r=>setTimeout(r,600));Guide.next();return document.getElementById('gd-title').textContent})()"
```

原生窗口本身用截图确认：标题应为「钢心 · Iron Mind」，
`logs\desktop.log` 里应能看到 `[desktop] 启动 ... port=...` 与
`[desktop] 内核就绪 http://127.0.0.1:.../`。
