# 19 编制变动：覆灭、殉国、二次整编

> 之前这三件事没人管：兵打光就把 `strength` 置零，番号、将领、命令原样留着。
> 后果是 AI 会继续去问一个已经不存在的军长"你要怎么打"，玩家看到一行
> "被全歼"，然后那支部队在列表里永远挂着 0.0 千。**编制没有变化，只有数字变了。**

---

## 1 覆灭是"状态"，不是"删除"

`Unit` 多了三个字段：

| 字段 | 含义 |
|---|---|
| `ended_day: Option<u32>` | 哪天没的。`None` = 还在编成内 |
| `reform_day: Option<u32>` | 预定整编完成日 |
| `reform_ratio: Fixed` | 整编后补到满编的几成 |

**为什么不把单位从 `Vec` 里删掉**：命令流、存档、前端快照全都按
**单位下标**引用部队（`{"unit": 9, "kind": "attack"}`）。删一个，后面所有
下标往前挪一位，历史命令会指向别的部队，回放、存档、`/api/replay-check`
全部失效。所以死亡必须是状态。

`is_alive()` 保持"兵 > 0"，另外加 `in_being()`（兵 > 0 且未被判定覆灭）。
AI、电报投递、LLM 问询都走 `is_alive()`，所以死掉的部队不会再有将领
对着空气下命令。

## 2 将领有结局：殉国 / 被俘 / 去职 / 突围

部队打光的那一刻掷一次骰（独立随机流 `stream::FATE`，同种子必然同结局）：

| 结局 | 概率 | 后果 |
|---|---|---|
| 殉国 `Killed` | 35% | 番号撤销，**不可能整编**（没干部拉起队伍） |
| 被俘 `Captured` | 15% | 同上 |
| 去职 `Relieved` | 20% | 同上（人已经离开这支部队） |
| 突围生还 `Active` | 30% | 若模块声明了整编，才有重建的资格 |

两条战报，可见性不同：

- `第4军 在 金官桥 被全歼` —— 双方都能看到（战场上看得见的事）。
- `第4军（欧震）全军覆没，欧震 殉国` —— **只报给本方**。
  敌人不知道对面的军长死没死，那是内部消息（`Event.side`）。

## 3 二次整编：要人，要后方

模块在 `oob.json` 里给某个单位写：

```json
{ "id": "cn.4", "name": "第4军", "reform_days": 25, "reform_ratio": 0.4 }
```

覆灭时若将领生还，就排下 `reform_day = 今天 + 25`。到那一天，
在**本方控制的下标最小的补给源省**重新成军：兵力 = 满编 × 0.4，
士气与补给 0.6，命令回固守。找不到补给源就一直等——后方被抄，重建就慢，
这条不需要额外规则，它是补给 BFS 的自然结果。

不写 `reform_days`（或写 0）= 打光就是打光了。**这是内容决定的事**：
1938 年有些师几个月里重建过两次，有些部队打光就再没有了。引擎不该猜。

> 目前只有 `第4军` 填了示例数据（25 日补到四成），`note` 里标注了是
> 用来验证流程的。其余 17 个单位都是"一次性"的。要按史实填，得先有
> 各师重建时间的资料——这件事我没编。

## 4 界面上看得见

- 部队列表底部多一段 **— 已覆灭 —**（灰度）：
  `第4军　金官桥　殉国　番号撤销` / `第187师　箬溪　在任　第40日整编`。
- 战报信箱多一个 **编制** 分类，`oob` 类事件默认进"重要"。
- 悬停能看到整编后的兵力比例。

## 5 测试（`crates/sim-core/tests/oob.rs`，6 个）

1. 覆灭只标记、不删除（`units.len()` 不变，`ended_day` 有值，命令与 `manual` 被清）；
2. 将领一定有结局，且不再是"在任"；
3. 同种子结局一致（连 `state_hash` 都一致）；
4. 整编的**充要条件**：将领生还 → 排上日子并真的重建；将领殉国/被俘/去职 → 不排；
5. 模块没声明 → 永不复活；
6. 将领死活只报给本方，敌方看不到"殉国/被俘"。

> 第 4 条要扫 40 个种子才能同时覆盖"生还"和"不测"两个分支——
> 0.7 的四次方也还是会有种子落到两个分支上，所以用循环而不是写死一个种子。

## 6 还没做（这次没碰）

1. **补充兵员**：`整补`（`Order::Rest`）现在只恢复士气，不恢复兵力。
   一支部队掉到 5/12 就永远回不来——这在 77 天的战役里不合理。
   要加"每日按补给源补入少量新兵"，但会改变全部战损节奏，得单独调平衡。
2. **番号传承**：现实里"第74军"打光后重建的部队，战绩与荣誉都继承。
   现在是同一单位对象原地复活，没有"新兵老兵"区别。
3. **编成树**：`formation` 还只是个字符串。兵团部被打掉会怎样？没定义。
4. **撤换**：`dissent_count` 已经有计数，但"抗命太多次被撤职"还没实现。
   它应该和 `Fate::Relieved` 接上——现在去职只在覆灭时出现。

## 7 兵团：从字符串到实体（P1）

以前 `formation` 只是一个名字。兵团部存不存在、在不在，都不影响任何事——
"打掉敌人的兵团部"在引擎里毫无意义，因为它没有实体。

现在 `World.formations: Vec<Formation>`，每个兵团有：

| 字段 | 含义 |
|---|---|
| `name` | 番号（`第29军团`） |
| `side` | 阵营 |
| `hq` | **兵团部所在单位的索引**（`第29军团` 自己既是部队、也是 `第187师` 的上级） |
| `units` | 下属单位（含兵团部自己） |

加载时按 `parent` 归组，`hq` = 名字与番号相同的那支部队。
找不到同名部队的番号（`第1兵团`）就是**纸面编制**：`hq = None`，
不加成也不惩罚——这本身是诚实的：数据里它没有兵团部。

### 影响：服从度

`obedience` 是抗命的唯一硬约束（规则 AI 与 LLM 提示词都读它）。
现在它是**实际服从度**：

| 兵团部 | 修正 |
|---|---|
| 在编 | +0.05（参谋部压得住师长） |
| 覆灭 | **−0.15**（没人压得住，师长只听自己的） |
| 纸面番号 | 无 |

兵团部覆灭还会额外报一条：`第29军团 兵团部覆灭，下属 1 部暂归战区直辖`。

这一条不需要新机制——只是让已有的数字反映编制状态。

### 测试（`crates/sim-core/tests/formation.rs`，5 个）

纸面番号无影响 / 兵团部在 +0.05 / 兵团部亡 −0.15 / 下限夹到 0 /
`formation_of` 覆盖到下属。
