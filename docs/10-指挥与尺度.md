# 指挥、上报与尺度

> 三个问题连着问：为什么只有"进攻"一个选项、为什么能对自己的省下令、将领该不该向我上报。
> 这三个问题其实是同一个问题的三个面：**玩家和将领之间的界面画错了**。
> 最后一段回答"省之下还能缩到多细"——答案是不能再缩省，只能在省内加层级。

---

## 1 三个症状，一个病根

### 1.1 命令只有四个动词，而且都是空间动词

现在的 `Order` 只有 `Hold / Attack / Move / Retreat`。四个词回答的都是"**去哪**"，
没有一个回答"**做什么**"。

一支打残了的师需要的是"整补"；一个省的守军需要的是"筑工事"；预备队需要的是
"待机，看到机会自己上"；被围的部队需要的是"突围"。这些都不是移动，所以现在
一个都表达不出来，只能退化成 `Hold`（然后什么都不发生）。

**这是词汇量问题，不是平衡问题。** 玩家感觉"只有进攻一个选项"，本质是：
唯一能产生可见结果的动作是 `Attack`，其余三个都表现为"什么都不发生"。

### 1.2 玩家在越级指挥，跟两级指挥的设计自相矛盾

设计文档里写得很清楚（`HANDOFF` 决策 5）：统帅部给方向，将领做解释——
可能打折扣、改目标、抗命。为此才有了 `obedience / initiative / aggression / caution`
四维和抗命判定。

但现在的交互是：**玩家点一个师，再点一个省，直接写进 `order`。**
这等于玩家取代了将领。于是：

- 四维性格只在 AI 互相打的时候有用，玩家自己玩时形同虚设；
- "抗命"变成一个只发生在敌人身上的机制；
- 玩家实际在玩一个 90 格的棋子游戏，而不是"下达意图、承担部下的解释"。

历史上真正的指挥张力恰恰在对面：**委员长越级打电话到师，薛岳就不执行。**
现在的实现里，这个张力被玩家的鼠标抹掉了。

### 1.3 上报通道不存在

右侧那一栏"战报"是 `world.log`：一条字符串数组，由规则引擎和系统往里面推。
它是一份**流水账**，不是**公文**。

区别在于：流水账没有收件人、没有发件人、不能回答、不承担后果。
将领现在不会请示任何事——他要么执行，要么静默抗命（`dissent_reason` 只出现在
单位的鼠标提示里）。玩家看不到"我该做决定了"，只看到"战线自己动了"。

## 2 命令：分两层，而不是加动词

加动词（增援、筑工事、休整……）只能缓解 1.1，解决不了 1.2。
正确的切法是**两层意图**：

### 2.1 上层：战役任务（玩家的主要操作）

玩家不点师，点**方向/兵团**，下达带优先级的任务：

| 任务 | 语义 |
|---|---|
| `hold_line` 守住某段 | 给定一串省，守住它们；丢了要报 |
| `take` 夺取某地 | 给定目标省或城市，多久之内 |
| `screen` 警戒/掩护 | 给定一个方向，只要求"别让人从这儿过" |
| `reserve` 保持预备队 | 不投入战斗，等玩家或将领调用 |
| `rest` 休整 | 撤到后方整补，恢复士气与补给 |

任务是**有期限、有优先级、可冲突**的。任务不指定哪个师去哪——
那是将领的事，也是`obedience × initiative` 起作用的地方。

### 2.2 下层：将领分解

引擎里已经有 `decide_side`（给每个单位一个 `intended`）+ `interpret`（将领解释）。
现在缺的是：这些决策的**输入**不该是"最近的敌人"，而该是**上级任务**。

改法很小：`intended` 的优先级从

```
残了就撤 → 邻接敌省就打 → 否则朝最近敌人走
```

变成

```
残了就撤 → 执行所属兵团的当前任务 → 没有任务才按性格自由行动
```

这样将领才真的在执行**你的意图**，而且会把它执行得跟你想的不一样。

### 2.3 干预：允许，但要收费

玩家仍然可以手动给某个师下令（现在的交互），这是"越级指挥"。
它不是免费的：

- 该师所属将领的`initiative`本 tick 归零（被打断了，不思考）；
- 记一次"越级"，累计到兵团层会降低`obedience`（"上面不信任我，那我也不担责"）；
- 手动命令的送达也要走通信延迟（`comms.order_delay`），**已经实现了**。

这条设计有牙齿：它让"亲自指挥"成为一个真实的取舍，而不是白送的便利。

## 3 上报：让将领有嘴

### 3.1 五种公文

引擎里加一个 `Report` 通道（**判定全在引擎，文字交给 LLM**）：

| 类型 | 何时发 | 玩家要做什么 |
|---|---|---|
| `Situation` 战况 | 打完仗 / 每天定时 | 无（读） |
| `Contact` 敌情 | 侦察到新敌情 | 无（喂情报系统） |
| `Request` 请示 | 将领判断需要决策 | **要选**（见 3.3） |
| `Advice` 建议 | 性格驱动的主动建议 | 可采纳可忽略 |
| `Disobedience` 抗命声明 | 抗命时 | 可追责可默认 |

现在这些信息散落在 `dissent_reason`、`log`、`intel` 三处，没有统一收件箱。
统一之后，右侧那一栏就从"流水账"变成"公文堆"。

### 3.2 走同一条延迟通道

关键点：**将领的报告也是一封电报。** 它要经过 `transmission + staff`，
跟情报在途、命令下达用的是同一套 `CommsConfig`。

这意味着：**你在指挥部看到的永远是过去的战场。**
将领三天前就在问你"要不要撤"，而那份请示还在参谋桌上——
这不是 bug，这是这个游戏想表达的东西。（`HANDOFF` 记的第 7 条决策）

### 3.3 请示：会过期

`Request` 带一个 `deadline`（默认 = `staff` 延迟 × 2 天）。到期没答复：

- 将领按**自己的判断**行动（`own_judgment`，已经实现了）；
- 记一次"上面没回话"，`obedience` 微降。

这一条是整个上报系统里最有价值的部分。它把"指挥链的摩擦"变成了可玩的东西：
你可以不回答，但你不回答本身就是一个决定。

### 3.4 LLM 在哪里

- **不**决定要不要请示（规则决定：兵力掉到阈值、邻接出现新敌情、任务无法完成）；
- **不**决定请示里推荐什么（`own_judgment` 决定）；
- **只**负责把结构化报告写成一个具体的人在该情境下会说的话。

理由跟抗命判定一样：经过 RLHF 的模型天然倾向"听从用户"，让它决定军情判断
它永远会给你一个四平八稳的答案。**判断归引擎，措辞归模型。**

## 4 尺度：省之下还能缩到哪

### 4.1 先把硬约束算出来

现在一个 tick = 一天。一个师一天能走多远？正常行军 20-30 公里，打仗时更少。

所以**一个省的直径应当 ≈ 30-40 公里**：一天走一格，一格就是一天的行程。
现在 90 个省铺在 470×315 公里的战区上，平均直径约 35 公里——**刚好在正确区间**。

由此推出两条：

1. **省不能再切细。** 切到 20 公里，一个师一天能走两格，"今天推进到哪"就没有决策含量了；
   要维持手感就得把 tick 降到半天，那是另一个时间尺度，整个战斗、补给、
   士气模型都要重标定。
2. **南浔线这个战区的省数上限约 90-120。** 超过之后开始出现"一个省放不下一个师"
   的荒谬感（堆叠上限 3 已经是这个信号）。要更大场面，正确的做法是**扩战区**，不是切细省。

### 4.2 想要更细，只能加"层"，不能加"格"

如果一定要比省更细，唯一的自洽做法是**省内的战术节点**，而不是第二张地图：

```
省 (35km)          作战尺度：玩家在这里下令
 └ 阵地 (2-5km)    战术尺度：将领在这里分配兵力，战斗在这里逐点解算
    └ 营连         不做。再往下就是《Close Combat》，不是这个游戏
```

一个省带 1-4 个阵地，每个阵地有：地形原型（`docs/04` 附录 A.2 那十种）、
宽度（展开正面）、工事等级。万家岭就该由「张古山 / 扁担山 / 哔叽岭」三个阵地组成，
而不是现在这样把三个山头画成三个省。

好处很直接，而且正好补上 P2 的坑：

- **战场宽度**：一个阵地的宽度决定能投入多少兵力。现在的"1.7 全灭 / 2.5 碾压"
  阈值问题，根源就是没有宽度概念——所有兵力都能同时展开。
- **反复易手**：一个阵地可以在几天里几次换手，而省的颜色不变。这才是万家岭的样子。
- **将领精细化指挥的下限**：将领调的是"哪个师去哪个阵地"，这是他该关心的粒度。

### 4.3 所以"将领能精细到哪里"

**到阵地。** 玩家到师，将领到阵地，营连不进模拟。

这是**战术层的下限**，不是方向的否定。项目一开始的目标就是战术游戏，
所以阵地这一层必须在引擎里；但营连级（单兵、单车、房间级 CQB）是另一个产品：
UI 要地图缩放、实体数 ×10 会拖垮哈希与回放、内容量也翻十倍。
战术游戏的下限是"排到团级、2-5 公里的阵地"，我们正好停在这条线上。

## 5 实施顺序（最小可用步）

按"改了立刻能感觉到"排序：

1. **修命令语义**（已做）——点击自己的省不该是"进攻"。目标归属决定命令类别：
   我方省 = 移防/增援，敌方空省 = 推进，敌方有兵 = 进攻。
2. **加三个状态动词**（已做）：`Fortify`（筑工事）、`Rest`（整补）、`Shift`（省内调兵）。
3. **兵团 + 任务**：把单位按 `parent` 归成兵团，玩家下任务，将领分解。
   这一步做完，`obedience/initiative` 才对玩家生效。
4. **Report 通道**：先做 `Situation` + `Request` 两种，接进已有的延迟通道。
5. **省内阵地**（已做）：逐阵地战斗 + 战场宽度，见第 7 节。

## 7 已落地（v0.6）

上面第 2-4 节不是设想，已经实现并跑起来了。

| 内容 | 落点 |
|---|---|
| 阵地层 | `world::Position { name, terrain, width, fort }`；`Province::positions` |
| 逐阵地战斗 | `run_combat` 按 (省, 阵地) 分组结算，不同阵地互不接触 |
| 战场宽度 | 每方战力先按 `width × 40 千人` 封顶，再乘地形与工事——多出来的兵只能当预备队 |
| 调兵 | `Order::Shift(n)`：省内换阵地，**不耗天数** |
| 筑工事 | `Order::Fortify`：原地挖，三日一级，工事在阵地上；遇敌自动停 |
| 整补 | `Order::Rest`：原地恢复补给与士气 |
| 玩家指挥权 | `Unit::manual`：玩家下过命令的单位，AI 不许覆盖 |
| 内容兼容 | `map.json` 不写 `positions` 就自动生成一个（省名 + 省地形 + 全宽度） |

**两条踩出来的硬规则**（写在这里免得下一个人重踩）：

1. **进攻必须打到有敌军的那个阵地。** 允许"挑最空的阵地"绕进去的话，
   攻方会专门绕过守军占一个空山头，双方在同一省里各占一个阵地、永不交战，
   省的颜色来回翻——看起来在打仗，实际谁也没碰到谁。
2. **玩家的命令不能被 AI 每 tick 覆盖。** 之前 `run_ai` 无条件给所有单位重新下令，
   玩家下的命令下一个 tick 就没了——等于玩家没在指挥，这也是"只有进攻一个选项"
   的真实原因之一：点了也白点。

万家岭现在是一个省、三个阵地：`张古山(宽0.4)`、`扁担山(0.6)`、`哔叽岭(0.5)`。
窄阵地投不进多余的兵，所以"把预备队从扁担山调到张古山"第一次变成了有意义的动作。

## 8 边界：这些各归谁

| 层 | 内容 | 归谁 |
|---|---|---|
| 内核 | tick、RNG、哈希、坐标 | 引擎（不可模块化） |
| 系统 | 战斗、移动、补给、情报、**上报投递** | 引擎（可 trait 化） |
| 指挥 | 任务类型、将领四维、抗命与请示判定 | 引擎（语义） |
| 内容 | 兵团的编成、任务文本、阵地划分、报告措辞 | 模块 |

判据还是那一条：**换一个战役，动的是数据还是代码。**
诺曼底不需要新写一种"报告"，只需要新的兵团和新的阵地划分。

## 9 还没做的（按下一轮顺序）

1. **兵团 + 任务**：现在玩家的命令还是逐个师下；有了兵团，`obedience/initiative` 才对玩家生效。
2. **Report 通道**：将领向你上报（战况/请示/建议/抗命声明），走已有的通信延迟，请示会过期。
3. **战斗加深**：阵地已有宽度，但解算还是"一方战力对一方战力"。
   下一步是预备队投入、突破与合围——宽度已经把那扇门打开了。
4. **阵地内容**：现在只有 4 个省有阵地。整个战区的阵地化是纯内容工作，
   `tools/mapgen` 的 `pos` 字段已经支持。
