# 架构对标：别人怎么做，我们哪里幼稚

> 你让我去看同类项目怎么做的。以下是我实际读过的四个，以及读完之后的结论：
> **我们现在的问题不是"功能少"，是三个地基没打**——输入没有命令日志、状态变化没有类型化事件、
> 渲染没有相机与增量。这三样都是同类项目的共同底线。

---

## 1 四个参照物

### 1.1 OpenRA —— 输入必须是"命令流"，不是"改状态"

OpenRA 的 `OrderManager` 是这类游戏的标准答案（[源码解读](https://blog.csdn.net/zhangzhechun/article/details/147659211)、[DeepWiki](https://deepwiki.com/OpenRA/OpenRA/3.4-order-processing-and-networking)）：

- 玩家的操作变成 `Order` **数据**，进 `localOrders` / `pendingOrders[client]` 队列；
- 按 `NetFrameNumber` **逐帧**取本帧该执行的命令，到帧边界才 `ResolveOrder`；
- 每帧算一个 **sync hash**，各端比对，不一致就是不同步，立刻报；
- **回放 = 种子 + 命令流**，不需要存世界快照。

关键不是"有队列"，而是：**世界状态可以从 (种子, 命令流) 重建**。所以能做回放、断线重连、
不同步检测、以及"把这一局发给别人复现 bug"。

我们现在是：点一下直接改 `World`，**没有任何记录**。于是刚才那些"点了没反应"我查不到，
你也没法把一局发给我复现。

### 1.2 NationFall —— 地图渲染迟早要离开 SVG

一篇很直接的开发日志（[Last Days Before Alpha](https://www.playnationfall.com/devlog/last-days-before-alpha)）：

| | SVG | Canvas |
|---|---|---|
| 1800 个多边形，4x 缩放 | **9 FPS** | 167-200 FPS |

他们的结论是：SVG 起步是对的（矢量边框、CSS hover、可访问性、点击目标全免费），
但**过了一千多个多边形、加上深度缩放就崩**，而且不是调优能救的，是渲染器的结构性上限。
换 Canvas 之后，他们把"每省的元数据、可访问性钩子、点击目标"**保留成一层并行的逻辑层**，
只把画像素这件事搬走。

对我们的启示有两层：
1. **现在 87 个省，SVG 是对的**，但**必须有相机（缩放/平移）**，否则 87 个省挤在一屏里，
   万家岭三个阵地只能靠标签硬挤——这就是你觉得"幼稚"的地方；
2. 一旦要到几百个省 × 阵地，就该换 Canvas，而且路径已经清楚：几何层与逻辑层分离。

### 1.3 Freeciv / freeciv21 —— 客户端只发意图，服务端裁决

Freeciv 的客户端（[client/control.cpp](https://github.com/jwrober/freeciv21/blob/12bf14675b3ed494d0a9673ad8db139fbcec770c/client/control.cpp)）
不直接改游戏状态，而是打包成 **packet** 发给服务端（`send_packet_unit_orders` 之类），
由服务端校验合法性、再广播结果。客户端永远不是权威。

我们现在也是这样（浏览器 → HTTP → 服务端 World），这一点是对的；但**校验只有三行**
（目标在不在、是否邻接、地面不能进水域），而且**没有回执**——前端拿到的是整份世界快照，
还得自己猜"我那条命令到底生效没有"。

### 1.4 Command Ops 2 —— 命令有延迟，下级会解释

[Command Ops 2](https://store.steampowered.com/app/521800/Command_Ops_2_Core_Game/) 最出名的机制就是
**命令下达有延迟、下级 AI 会自己判断怎么执行**：你下的是意图，不是像素级操作。
这跟我们 `docs/10` 里写的两级指挥是同一个思路——但人家真的把它做成了**看不见的手**，
我们只有 `obedience/initiative` 四个数字在场上跑，玩家感受不到。

## 2 逐项对照：我们幼稚在哪

| 维度 | 同类项目 | 我们现在 | 后果 |
|---|---|---|---|
| 输入 | 命令对象 → 队列 → 帧边界执行 → 命令日志 | 点一下直接写 `World`，无记录 | 不可回放、不可复现 bug、不可撤销 |
| 回执 | 命令被接受/拒绝，附原因 | 返回**整份世界快照**，没有回执 | 前端只能靠状态猜，出错无法定位 |
| 事件 | 类型化事件流（战斗/占领/抗命…） | `Vec<String>`，前端用正则给字符串上色 | 加事件必须改前端正则；战斗根本没有事件 |
| 渲染 | Canvas/分帧 + 相机（缩放平移） | 每次变化 `svg.innerHTML=""` 全量重建，**没有相机** | 87 省挤一屏；一帧全重画 |
| 交互 | 拖拽平移、滚轮缩放、框选、右键菜单、快捷键 | 只有单击 + 悬停 | 玩家只能"一个一个点" |
| 时间 | 暂停/变速/到下一事件 | 只有"推进 1/3 日" | 无法边看边想 |
| 存档 | `(种子, 命令流)` 或快照+版本 | **没有** | 关掉就没了 |

最刺眼的一条：**战斗没有任何战报**。右侧栏那些"山地行军非战斗减员"全是模块规则推的，
真正的伤亡、易手、击溃，一件都没写。所以玩起来像"点完看颜色变"。

## 3 v2 架构（定下来，按这个改）

### 3.1 传输层

```
GET  /api/state?since=<seq>    → 首帧全量；之后只回 (seq, events[])
POST /api/command              → { ok, seq, 拒绝原因? }   不回快照
GET  /api/log                  → 人类可读操作日志（已有）
```

前端持有一份自己的世界模型，靠事件增量更新；`seq` 单调递增，断线重连时按 `since` 补齐。

### 3.2 命令

```rust
struct Command { day: u32, seq: u32, unit: Option<u32>, kind: CmdKind, target: Option<u32> }
```

- **全部落盘**（`Vec<Command>`），`(module_hash, seed, commands)` 就是一份完整存档；
- 应用点在 tick **边界**，同一 `day` 内按 `seq` 排序 → 确定性；
- 合法性由服务端裁决，拒绝要带原因（前端 toast 直接显示）。

### 3.3 事件

```rust
struct Event { seq: u32, day: u32, kind: EventKind, text: String }
enum EventKind { Command, Combat, Occupy, Retreat, Dissent, Intel, Supply, Rule }
```

引擎负责产出（战斗、团灭、易手、抗命、工事完工、侦察首次接触），前端按 `kind` 决定样式，
不再用正则匹配中文。战报从此是**数据**，不是字符串。

### 3.4 渲染

- **相机**：`viewBox` 就是相机（滚轮缩放、拖拽平移），SVG 的原生命中测试跟着走，不用重写拾取；
- **分层**：几何层（省多边形）/ 标记层（单位牌、阵地）/ 文字层（标签）/ 覆盖层（可达高亮、行军线）；
- **增量**：只在状态真的变了才重建，且分图层重建（地形变不必重建单位牌）；
- **换 Canvas 的阈值**：省 + 阵地合计超过 ~800 个多边形，或缩放帧率掉到 30 以下，再上 Canvas。
  路径照 NationFall：几何与逻辑分离，命中测试留在逻辑层。

### 3.5 时间控制

暂停 / 推进 1 日 / 推进到下一事件。最后一项依赖 3.3 的事件流——没有事件流就做不了。

## 附：存档槽位（P3）

存档一直是"一份最新的文件"（`saves/save-<时间戳>.json`），想回看上周那一局没有办法。

现在：

- `POST /api/save {"slot": "南浔-01"}`：存到 `saves/<slot>.json`；不给 slot 就按时间戳（向后兼容）
- `GET /api/saves`：列出所有槽位（名字、模块、天数、命令条数、修改时间）
- `POST /api/load {"slot": "南浔-01"}`：按槽位读；仍支持 `path`；都不给就读最新一份
- 界面：存档/读档按钮改成弹输入框（读档会列出所有槽位让你选序号）

槽位名会被拼进文件路径，所以**服务端必须消毒**：
只留字母数字（含中文）、`-`、`_`，其余换成 `-`，最多 40 字。
`../../../etc/passwd` → `etc-passwd`，`..\..\x` → `x`。
这条有单元测试（`sanitize_slot`）。

### 踩到的坑：结构体字面量里的两次 `lock()`

`SaveFile { module_id: state.module.lock()...， module_version: state.module.lock()... }`
看起来是两次独立加锁，实际**临时 guard 活到整条语句结束**——
第二次 lock 就是自死锁（std 的 Mutex 不可重入）。
表现：`POST /api/save` 永远不返回，而其他请求（不碰这把锁）照常工作，
日志里只有一行 `POST /api/save body=...` 就再没下文。
先把两个字段取成局部变量再构造，问题消失。
