# 指挥即通信

> 这是一次交互模型的重写：从"棋子游戏"改成"指挥游戏"。
> 地图只用来**看**。玩家唯一的动作是**发电报**，将领决定怎么执行。

---

## 1 为什么改

之前是：点单位 → 点相邻省 → 命令直接生效。
这有三个问题，而且是同一个根：

1. 玩家在**绕过指挥链**。将领的性格、抗命、延迟全部失效——因为命令是他自己下的。
2. 这游戏**没有"传达"这件事**。而 1938 年的战争，最要命的就是命令传不下去、传下去了也不照办。
3. 一百多个省、十几个师，玩家在玩**棋**，不是在**指挥**。

所以：**地图只作查看，命令一律变成文字，交给将领。**

## 2 唯一的入口：电报台

```
发给 [第1兵团 ▾]
┌────────────────────────────────────────┐
│ 守住德安到万家岭一线。张古山工事加厚，   │
│ 不许拿部队去拼消耗；没有把握的进攻一律不批。│
└────────────────────────────────────────┘
          [ 发出电报 ]
```

一封电报的完整生命周期：

```
起草 →（在途：按通信配置延迟 1-N 日）→ 送达番号
     → 该番号下**每个将领各自**读这封电报
     → 每人给出：自己的判断 + 是否照办 + 一句回电
     → 有异议的先来「请示」；照办的写进命令流
     → 回电汇总挂在这封电报下面
```

实测一封电报的回电（真实 DeepSeek，原样）：

> **王敬久**：遵令筑工事，城垣、张古山加厚，不轻出消耗。补给不足四成，请速补弹药。
> **俞济时**：遵令加厚张古山工事，另派搜索队前出马马回岭方向查明敌情，有把握再报请出击。
> **欧震**：职部创工事于金官桥，正面无敌踪，未敢空耗兵力远出；待敌情明再图进取。
> **叶肇**：职于星子加筑工事，扼住正面，不浪战。敌若沿湖岸来，请示准我向隘口机动侧击。

同一条电报，四个人四种执行：一个要弹药、一个派侦察、一个不动、一个反过来要你批准他侧击。
**这就是这次改版想要的东西。**

## 3 边界：玩家不能做什么

| 能做 | 不能做 |
|---|---|
| 看地图、点部队看详情、右键看阵地 | **直接调兵**（`/api/order` 已关闭，返回"请发电报"） |
| 给某个番号发电报 | 指定某个师具体走哪一格 |
| 批复/驳回将领的请示 | 替将领决定打不打 |

`POST /api/order` 现在固定返回：

```json
{"error":"不能直接调兵。请向将领发电报，由他决定怎么执行"}
```

前端也删掉了筑工事 / 整补 / 换阵地三个按钮和"可达省份高亮"——
那些都在暗示"你能点它下令"，与设计冲突。

## 4 为什么这是"更真实"而不是"更麻烦"

因为**距离与误解**变成了机制，不再是数值：

- 电报在途 1 日 → 你看到的是昨天的战场。
- 番号下 4 个将领收到同一条电报 → 各自理解不同。
- 兵力不足的那个会说"请速补弹药"——那是他的处境，不是你要的答案。
- 请示会过期（2 日），不答就是让他自决。

## 5 确定性怎么办

电报本身不进模拟。链路是：

```
电报文本 → LLM → 命令（CmdRecord, source="llm", reason=回电）→ 命令流 → 世界
```

回放仍然只读命令流，不重新问模型。`/api/replay-check` 照旧通过。

## 6 成本

- 一封电报最多问该番号下 **6 个** 将领（超出只问前 6 个）。
- 第1兵团 有 4 个师 → 一封电报 4 次调用。
- 例行问询（每 N 日一次）仍然开着，用来看没有收到电报的部队。

## 7 还没做

- **兵团任务**：现在是"每次一发电报"。真正的大战略是"给一条任务线"，
  电报只是临时干预。（`docs/10` §2.1）
- 电报模板/快捷短语：手机上打字太慢，需要"守住某段/夺取某地"的快捷式。
- 地图上画电报流向与在途标记。
- 将领回电的**归档**：现在只挂最近的电报上，久了会被挤掉。
