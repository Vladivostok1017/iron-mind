# 将领大脑：把 LLM 接进来，但把机械边界留在引擎

> 前一版我写的是"抗命判定绝不能交给 LLM"，理由是 RLHF 让模型天然顺从。
> 这个判断错了一半：**顺从是可以用提示词硬顶的**，用"禁止"换来的不是安全，
> 是把整个设计目标（AI 驱动的将领）丢掉了。这一版按正确的方式接。

---

## 1 分工：LLM 判断，引擎执行

| 谁 | 负责 |
|---|---|
| **LLM** | 这个将领此刻该干什么、为什么、愿不愿意照上级的命令办 |
| **引擎** | 命令合不合法、战场怎么结算、状态怎么变、回放怎么复现 |

引擎不知道"谁聪明"，它只知道一条命令。所以模型换掉、超时、胡说八道，
模拟本身不会坏——最坏结果是这个将领这一天没动作。

## 2 确定性边界（这条是硬要求）

模型输出**不进** tick，只进命令流：

```
LLM 判断 ──► CmdRecord{day, unit, kind, target, source:"llm", reason} ──► 世界
                     │
                     └─ 存档 = 命令流；回放 = 重放命令流，**不再问模型**
```

实测（第 6 日，8 条命令其中含 LLM 命令）：

```json
{"ok":true,"day":6,"commands":8,"applied":8,
 "live_hash":"32e75fd010100b1e","replay_hash":"32e75fd010100b1e"}
```

这一条过了，才谈得上回放、存档、复现 bug。**模型不确定，但整局仍然确定。**

## 3 反谄媚：靠提示词，不靠墙

系统提示词里直接点名这个偏误（原文摘录）：

> 【必须主动对抗的偏误】大语言模型在训练中普遍被奖励"顺从提问者"，于是会不自觉地把"照办"当成正确答案……本场景恰恰奖励独立判断。所以：
> 1. 先独立判断此刻正确的军事行动，再看上级要你做什么；两者不一致时，说出不一致；
> 2. 即使你最终决定照办，也必须先写出至少一个"不照办"的理由；
> 3. 如果你照办，必须写出你为此接受的具体代价（兵力、时间、阵地、退路）；
> 4. 不要恭维，不要套话，不要自称AI，不要复述命令原文。

**结构化输出**逼它把话说完整：

```json
{"order":"attack|move|retreat|hold|fortify|rest|shift",
 "target":"省名或阵地名","dissent":true,"confidence":0.6,
 "reason":"不超过80字，你自己的判断","cost":"照办时你接受的代价"}
```

实测这就是它写出来的东西（第 5 日，原样摘录）：

> **第9师团（吉住良辅）**：不照办的理由：敌军主力两万余在万家岭山地，我军1.93万若只蹲工事，等于把主动权交给对方。但城垣工事仅1级、补给半空，仓促出击无胜算，先筑工事固守、补足粮弹再寻机。（代价：耗费一日工期，放弃对万家岭的试探性压迫，阵地仍取守势。）

> **第27师团（本间雅晴）**：当面万家岭敌近两万三，我万四千五，工事仅一级。上级令筑工事方向对，但仅固城垣不够——须同时在东门预置退路，防被山地之敌压向江岸。（代价：固守待敌，放弃向东扩张的窗口……）

> **第6师团（稻叶四郎）**：敌军全在邻省为零，此刻筑工事纯属空转。但梅川是孤点，工事是以后被围时的唯一退路，先修不亏，同时保留侦察机动。（代价：24千兵力原地停滞一日……）

这些不是客套话，是**带反对意见的执行**。这就是原先想要的东西。

## 4 只给将领他知道的

提示词里只有：他自己的兵力、士气、补给、位置、阵地工事，
以及**本方的邻接敌情估计**（`enemy_estimate`，带误差和时效的推测值）。

**不喂真值。** 他判断错了，是因为他消息不灵——这比"AI 算得准"更接近这场战争。

## 5 异步与成本

| 机制 | 取值 | 理由 |
|---|---|---|
| 问询线程 | 一条后台线程 + 就绪池 | 模型要几秒，不能卡住"推进一天" |
| 生效时点 | tick 边界（`day <= now`，最旧 3 天） | 保证模拟顺序不被网络抖动打乱 |
| 同一单位间隔 | `IRONMIND_LLM_INTERVAL`，默认 3 日 | 将领不会每天改主意 |
| 每日上限 | 3 单 | 防止一次推进几十天时爆量 |
| 超时 | 40s（`IRONMIND_LLM_TIMEOUT`） | 超时即放弃，规则 AI 顶上 |
| 失败退化 | 无 key / 超时 / 解析失败 → `ai.rs` | 游戏永远能玩 |

## 6 命令怎么落地

- 模型给的 `target` 是**省名**，按名字解析成 id；解析不出来 → 当成"按兵不动"（不瞎打）。
- 判断与现有命令**一致** → 不改命令，只往战报里写一条他的表态。
- 判断**不同** → 覆盖命令、标记 `manual`（本 tick 规则 AI 不许改）、记抗命战报。
- 一切落地都走 `apply_record()`，**实时和回放共用同一段代码**——两条路径一旦分叉，回放校验立刻会挂。

## 8 已知问题

1. **成本不可控在长局**：18 个单位 × 每 3 日 = 每 3 日 6 单。一天推 30 日就是 60 单。
2. **模型会编地名**（"向东门方向试探"这类没问题，但可能写不存在省名）——已有按名解析 + 拒绝，但会让这一天白问一次。
3. **回放必须带命令流**：只有种子是回放不出来的。存档已经这么做了，但"分享一局"还没有导出入口。
4. ~~没有记忆~~ **已修**：见第 9 节。

## 9 人物志：让四个小数长成一个人

只有 `obedience/initiative/aggression/caution` 四个数字，模型只能按小数臆想一个军官。
所以 `oob.json` 的 `commander` 多了三段文本（**只给 LLM 读，不进模拟、不进状态哈希**）：

```json
"commander": {
  "name": "松浦淳六郎", "obedience": 0.8, "initiative": 0.6,
  "aggression": 0.7, "caution": 0.4,
  "title": "第106师团长",
  "persona": "熊本人，做过第6师团旅团长，熟悉山地战。性好冒险，常说“山地里人少反而好办事”。",
  "agenda": "第106是新编师团，他急于一战立威，敢把部队往深山里带——这是他的贪，也是他的死穴。"
}
```

- `persona` = 他是谁（出身、经历、用兵习惯）
- `agenda` = 他图什么、怕什么（**给模型一个可以拿来做私心权衡的抓手**）

十八个将领全部写了。效果是能直接看见的（第 6 日原样摘录）：

> **第27师团（本间雅晴）**：工事未成前出击是拿**最差装备的临时师团**赌万家岭二十余万之敌……

> **第6师团（稻叶四郎）**：工事只加半档……不如放骑兵继续搜龙坪沼泽，**别把师团钉死在梅川**（代价：**抢梅川以东头功的窗口再缩一日**）

> **第101师团（伊东政喜）**：不照办的理由：工事挡不住金官桥12.1千与星子8.4千的夹击，固守山地隘口是**把新兵钉死在死地**……

“临时师团装备最差”“不能让别人抢头功”“特设师团经不起大伤亡”都来自 `agenda`，
不是模型自己编的。人物志写对了，它就会替你想出该有的顾虑。

## 10 记忆：让抗命变成连续叙事

问询是无状态的，同一个将领每天会重新掷一次骰子。所以每次问之前，
从他的**命令记录**和**战报**里捞最近几条近事，塞进提示词：

```
你自己近来的事（你说过的话、你遭遇的事）：
- 第4日 第9师团 损失 0.6 千，第106师团 损失 0.3 千
- 第5日 我主张 fortify（已执行），理由是「城垣工事仅1级、补给半空……」
```

- 来源：`CmdRecord`（他自己下过的 llm 命令，含理由）+ `world.log`（含他番号的战报，只取近 6 日）
- **不进世界状态**：回放靠命令流，不靠记忆；记忆只影响"下一次问模型时它看到什么"，
  而那次回答本身已经被记进命令流了，所以确定性不受影响。
- 一个将领现在会说"照办不亏，但……"——因为他记得上次照办之后发生了什么。

**顺带产出**：战报里现在带 `（把握 72%）`，以及 `〔有异议，仍照办〕`。
玩家看到的不再是"命令已下达"，而是"这个人有多大信心、是不是憋着话"。

## 附：非玩家阵营的"假指挥官"（统帅部）

之前非玩家阵营**没有指挥部**：八个师团各自看一眼邻省、各自决定打不打。
行动像八个独立军阀，而不是一支有作战方针的军。（史实里第 11 军司令部
是有的——"沿南浔线南下、相机夺取南昌"。）

注意一个容易搞混的点：**每个师团本来就是 LLM 在指挥的**（`request_due`
对双方的单位都会发问）。缺的不是"给日军装个 AI"，而是缺一个
**在师团之上给方向的东西**。

所以补的是 `sim_core::ai::theater_facts(world, side)`：一份**确定性、
不额外花钱**的**战区态势**。

### 它只报事实，不给判断

这条边界是刻意划的，1.5.x 之后收紧过：

| 它报什么 | 怎么算 |
|---|---|
| 双方有效战力 | `total_combat_power`（含工事与士气折算，**不看人头**——进攻方历史上普遍人少，只看人头会让入侵者永远被算成"该收缩"） |
| 够得着的敌方省 | 只列"邻省驻着本方地面部队"的敌方省，最多 4 个，按设施多寡排序 |
| 每个目标的设施 | 补给源 / 铁路 / 工事 N 级（模块里写死的属性，不是推断） |
| 每个目标的守军 | 省内敌方地面部队兵力合计 |

**它不给"该推进还是该收缩"，也不给"主攻方向"。**

早先的版本叫 `theater_plan`，会算一个 `posture`（推进 / 巩固 / 收缩）写进
将领提示词。后果是：将领读到的不是"敌我多少兵、哪些要点够得着"，而是
"司令部建议推进"；它抗命时引用的也是这句建议 —— 判断实际上是那个函数做的，
"抗命"退化成"照着结论找理由"。这是**同一件事被算了两遍、便宜的赢**。

### 三个用途

1. **LLM 将领的提示词里多一段事实**：

   > 当面态势（只有事实，不含任何建议）：我 12.4 千 / 敌 6.8 千（战力比 1.82）。
   > 与我方地面部队相邻的敌方省份（按设施多寡排序）：东华门（补给源、铁路）
   > 守军 3.2 千；建国门（工事 2 级）。

   后面跟一句"怎么解读由你自己判断：该进、该守、该退，都是你的结论"。
2. **玩家自己的态势行**：顶栏 `当面：12.4 / 6.8 千（战力比 1.82）· 够得着：东华门、建国门`，
   悬停看完整事实句。**这不是"司令部的命令"** —— 玩家就是最高指挥；
   早先这行写"司令部：推进 → …"，被误读成"上面还有个司令部在给我下命令"。
3. **规则 AI 不读它**。`crates/sim-core/src/ai.rs` 里没有任何调用点：
   `decide_side` / `pick_target` 自己看代价场（`cost_field`）算方向。
   （旧文档写"规则 AI 照它办事"，那是错的，已改。）

> 这条刻意**没有**做成第二个模型。原因是：数战场是确定性的，用规则算既便宜
> 又可复现；真正需要模型的是**师团长在具体处境里的判断**（要不要抗命、
> 值不值得打），那才是 LLM 该花的钱。

### 将领能看见的地图状态（1.5.2 起）

以前提示词里只有自己的阵地 + 邻省兵力估计，缺三样东西：**友军在哪**、
**铁路通不通**、**对面是谁**。补齐后长这样：

| 类别 | 给什么 | 精度 |
|---|---|---|
| 自己 | 兵力/满编/士气/补给、职务、人物志、记忆、服从度 | 精确 |
| 所在阵地 | 省、阵地名、地形、控制方、本阵地工事、展开宽度 | 精确 |
| 邻省 | 归属、地形、**敌军估计**、铁路状态（通车/坏 N 级/已炸断）、是否补给源、**已认出的番号** | 估计 ±40% |
| 远处（2-7 日行程，≤10 个） | 同上 + 要走几天 | 估计 |
| **附近的我方部队** | 名、所在省、兵力、当前命令（"进攻"/"固守"…） | 精确 |
| **本方补给源** | 省名清单 | 精确 |
| 当面态势 | 双方有效战力、战力比、够得着的敌方省与其设施与守军 | 我方精确、敌方估计 |

两条硬规矩：

1. **敌方数字一律来自情报表**（`intel.rs`），不读真值。哪怕部队真值变了，
   只要情报没刷新，将领看到的还是旧的估计 —— 这才是迷雾。
   （1.5.1 及以前 `theater_plan` 读 `total_combat_power(enemy)`，等于把敌方
   全图兵力精确值塞进每个将领的提示词；守军则读 `units_in()` 真值。
   两处都已收口，测试 `enemy_numbers_come_from_intel_not_truth` 守着。）
2. **番号只有认出来才给**。情报里的 `identity_known` 是"第一次接触认不出、
   第二次才认出"，之前从来没进过提示词 —— 那个机制等于白做。现在认出来
   就写成"番号 第106师团"。

友军给的是**状态不是判断**（"第74军 在 沙河（12.0 千，当前进攻）"），
将领要自己决定值不值得指望他、要不要替他挡。

### 测试（`crates/sim-core/tests/plan.rs`，8 个；`llm.rs` 另有 2 个）

同一态势同一份事实 / 只列够得着的敌方省 / 报出双方兵力、兵力比与守军 /
设施是"列出来"而不是"排成计划" / **摘要里不许出现"推进、巩固、收缩、建议、
主攻"等判断性措辞**（这条是这组测试的重点）/ 没有够得着的敌方省时给空目标。
## 附二：敌方也有一个"玩家"（统帅部 / AI 玩家）

上一节补的 `theater_facts` 只是**一段给将领看的事实**，它连建议都不给。
真正缺的是：非玩家阵营没有**一个人在统领全局**。

现在有了：`HqDef`（内容层声明）+ `HqDriver`（服务端一条独立线程）。
内容里写他是谁、想干什么：

```json
"hq": {
  "name": "岡村寧次", "title": "第11军司令官",
  "persona": "情报参谋出身……宁可晚三天也不愿让一个师团在半路上断粮。",
  "agenda": "打通南浔线、相机拿下南昌，但更怕师团被各个击破。",
  "objectives": ["沿南浔铁路南下，夺取德安", "保护长江水路补给线", "避免单个师团孤军深入"]
}
```

他每隔几天（`IRONMIND_HQ_INTERVAL`，默认 4 天）开一次会：

1. 服务端把**他自己视角**的态势交给他——麾下各部的番号/位置/兵力/补给/命令/
   是否被围，加上**已知敌情**（走情报视图，不是真值），加上上一阶段的方针；
2. 模型回 `{"plan": "...", "orders": [{"to": "第106师团", "text": "..."}], "reason": "..."}`；
3. **他的命令变成电报，发给师团长**，走的是和玩家完全一样的通道：
   `Ask{incoming}` → 师团长自己的判断 → 可以抗命。
   日志里能看见 `司令部 → 第6师团：向当面之敌推进，占住要点。`

于是敌方的指挥链和玩家这一侧是对称的：

| | 玩家侧 | 敌方 |
|---|---|---|
| 最高指挥 | 玩家（人） | 统帅部（LLM） |
| 下达方式 | 电报台 | 同一条电报通道 |
| 执行 | 将领判断，可抗命 | 同 |

刻意保留的两处不对称：
- 敌方的态势**不给玩家看**（那是情报）；玩家只看到自己这一方的
  （顶栏那行"当面：X / Y 千 · 够得着：…"，那是 `theater_facts` 数出来的，
  便宜且确定，且**不含判断**）。
- 统帅部只在**模块声明了 `hq`** 时才存在。没有就不做——不是每个模块都想
  给敌国一个"人"。

测试：`llm.rs` 的 `hq_tests` 三个（假司令官给出方针与电报、被围部队收到的是
固守而非推进、提示词里带职务/目标/麾下/敌情/被围标记）。
