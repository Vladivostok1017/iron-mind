## P0 —— 没有它就不算一个"游戏"

### 1 结局系统 ★ ✅

战役打到第 77 天必须有句话。不是"你赢了"，是**多个结局**（`docs/05` 的谱系），
而且**由模块声明**：引擎只提供句式（指标 + 比较 + 优先级），
内容决定"什么算苦撑、什么算溃败"。

- [x] 引擎：`World.outcome`、`endings::evaluate()`、战役天数上限
- [x] 内容：`scenario.json` 的 `endings`（5 条，够用）
- [x] 服务端：到日子自动判定、`/api/tick` 拒绝继续、快照带 `outcome`
- [x] 界面：结局面板（名字 + 一段话 + 关键数字 + 对比历史基线）
- [x] 测试

### 2 补充兵员 ★ ✅

`整补` 现在只恢复士气，不补人。77 天的仗打到后期所有部队都是残废，
再没有恢复手段。要有：在补给良好的己方省里 `Rest`，每天补一点兵，
上限 `max_strength`。

### 3 推进到下一件事 ★ ✅

现在只能"推进 1 日 / 5 日"。玩家真正要的是「**推进到下一封电报/公文/战报**」。

- [x] 服务端：`POST /api/advance`，推进到日志增长或战役结束（上限 30 日）
- [x] 界面：一个按钮 + 键盘 `空格`

## P1 —— 战场该有的东西

### 4 合围判定 ✅

现在断供靠"补给线上有敌人"。真正的合围（**所有邻省都是敌军控制**）
应该额外一层：被围部队补给按 0 计并掉士气。万家岭围歼战的核心就是这个。

### 5 行军线画在地图上 ✅

部队在路上时，地图上从当前省到目标省画一条虚线 + "剩 3 日"。
现在只能从侧栏数字看出部队在动。

### 6 兵团建制实体 ✅

`formation` 只是个字符串。兵团部被打掉应该影响下属部队的服从与协同；
`第1兵团` 也该有自己的位置与参谋。

### 7 情报延迟与误判 ✅（近似 ±40% 误差、在途报告、精度衰减、番号需两次接触）

现在情报精度是"侦察到就准"。应该加上：侦察也有延迟、有概率误判、
敌方番号需要接触两次才认得出。

## P2 —— 让空海军成为兵种

### 8 海战 ✅

两支舰队同处一段水道 → 炮击 + 吨位损耗。现在互相看不见。

### 9 制空权 ✅

两军空军同空域互耗；空袭效率按制空权打折。

### 10 行军纵队被空袭 ✅

现在只炸停在省里的部队。106 师团在万家岭被围，一半原因是行军纵队被咬住。

### 11 铁路与水道运力 ✅

南浔铁路是这场战役的命脉。现在 `supply_throughput` 只是省上一个常数，
而且**水路补给被直接跳过**（日军的长江补给线完全没有体现）。
