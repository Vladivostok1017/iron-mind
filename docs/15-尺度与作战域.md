# 尺度、作战域与真实底图

> 两份升级：模块能声明**自己是什么尺度**（攻坚 / 战线 / 海战 / 空战），
> 地图底下垫**真实水系**（长江、赣江、鄱阳湖），不再是一堆抽象色块。

---

## 1 模块现在会声明自己是哪一类战役

`module.json` 新增两个字段：

```json
"scale": "siege",
"domains": ["land"]
```

| `scale` | 含义 | 规模校验 | 额外要求 |
|---|---|---|---|
| `theater`（默认） | 战役级：几十到上百个省 | 建议 ≥12 省 | — |
| `battle` | 战斗级：几个省，逐阵地争夺 | 2–12 省 | **每个省都要拆阵地** |
| `siege` | 攻坚：一两个要塞 | 1–6 省 | **每个省都要拆阵地** |
| `naval` | 海战/江防：水域占大头 | ≥2 省 | 建议声明 `naval` 域 |

`domains` 声明本战役涉及哪些作战域：`land` / `naval` / `air`。校验器会双向检查：

- 声明了 `naval` 却没有海军单位 → **错误**
- 声明了 `naval` 却没有水域省份 → **错误**
- 声明了 `air` 却没有空军单位 → 警告
- 声明了 `land` 却没有地面单位 → 错误

**引擎代码里不区分这些尺度。** 它只认省、阵地、单位、水域——
所以"支持不同尺度"不是加一堆 if，而是加**声明 + 校验**，让模块自己说清楚，
让校验器在加载时就把它拦下来。

### 已经跑通三种尺度的模块

```bash
cargo run -p sim-testbed -- --module content/scenarios/nanxun_1938.imod --ticks 60   # theater
cargo run -p sim-testbed -- --module content/scenarios/demo_1805.imod   --ticks 20   # battle
cargo run -p sim-testbed -- --module content/scenarios/siege_tianjiazhen.imod --ticks 6
```

攻坚模块 `siege_tianjiazhen`：3 个省、4 个单位。田家镇要塞工事五级（主堡 5 / 东炮台 4），
日军第6师团今村支队从富池口方向压上来。实测 6 日：

```
[0] 田家镇要塞·主堡：要塞守备队 损失 0.1 千，第6师团今村支队 损失 0.4 千
[3] 半壁山·主峰：第198师 损失 0.2 千，第6师团今村支队 损失 0.2 千
```

同样兵力比，在开阔地是另一个结果——**工事与阵地宽度把"攻坚"和"野战"区分开了**，
不需要额外写一套战斗规则。

## 2 真实地理底图

省份是 Voronoi 切的，形状天然抽象。所以在地图底下垫一层真实水系：

- 数据：**Natural Earth 1:50m**（公有领域），取 coastline / rivers / lakes
- 处理：裁到战区范围（112.5–118.6E，27.0–31.6N）、保留 3 位小数、按最小间距抽稀
- 结果：**8.6 KB** 的 `crates/sim-server/web/basemap.json`，随服务端一起编译进去
- 渲染：河流与湖泊画在省份填色**之上**（省色是"归属"，河湖是"地理"，两层叠起来才像地图）

生成脚本：`node tools/mapgen/basemap.js`（优先读 `tools/mapgen/_geo/` 下的缓存文件，
避免 Node 的 fetch 被重置）。

**为什么放服务端而不是模块里**：按 `docs/04` 的分层，G0 全球底图（海岸线、主要水系）
归**引擎**，G1 战役省份归**模块**。换战役不用重画底图。

## 3 还没做的

- **省界贴合地形**：现在仍然是 Voronoi，只是底下有了真实水系。要更真，
  需要用真实县界（GADM）做约束——那会把 Voronoi 变成"加权 Voronoi"或直接改用真实多边形。
- **高程底纹**：Natural Earth 有 raster 版本，但体积大；需要先决定是打包还是按需下载。
- **时间尺度**：攻坚战一小时一级、战役一天一级，现在是统一的"一天一 tick"。
  真要分开，得把补给/士气/战斗的全部系数按 `ticks_per_day` 重标定，是另一件事。
