# 20 补给：能不能切断，断了会不会死人，战报要不要走邮路

> 三个问题一起答，因为它们是同一个问题的三面：
> **后勤在引擎里是不是真的存在。**

---

## 1 补给怎么流（改动前）

`compute_supply` 从本方**补给源**做 BFS，每过一省 ×0.75 × 省的 `supply_throughput`：

```
补给源(1.0) → 0.75 → 0.56 → 0.42 …
```

然后每个单位的 `supply = level + (1−level) × supply_reach`，
在**敌省**里取"就地征发 0.5"与延伸补给的高者。

问题是它**只认归属**：只要省还是我的，补给照常流，
哪怕敌人一个联队正蹲在公路上。

## 2 切断补给线（新）

BFS 经过某省时先看一眼：**这个省里有没有敌方的地面部队**。
有就算"被截"，该段通行能力 ×0.3。

```rust
let interdicted = world.units_in(nb).iter().any(|&i| {
    let u = &world.units[i as usize];
    u.is_alive() && u.kind.is_ground() && u.side != side
});
let pass = if interdicted { Fixed::ratio(3, 10) } else { Fixed::ONE };
let cand = cur_level * decay * np.supply_throughput * pass;
```

截一段 −70%，截两段剩 9%，基本就断了。这是"穿插到敌后打补给线"的落点：
以前这种行为在引擎里**完全不存在**，因为归属没变，补给照流。

## 3 断水断粮就真的打不了，而且会死人（新）

以前补给只影响 `combat_power = 兵力 × 士气 × 补给 × 系数`：
补给 0 → 战斗力 0（打不了），但**永远不减员**。一支部队可以在包围圈里
蹲到战役结束，兵一个不少。

现在加 `run_starvation`：

| 条件 | 后果 |
|---|---|
| 补给 < 0.15 | 日损 **0.5%** 兵力、士气 −2%，每 3 天一条战报 |
| 补给他处 | 无 |

0.5%/日 的量级：一支 8 千人的军断粮一个月掉到约 6.9 千。够痛——逼得你去
打通补给线，但不至于三天蒸发（留出救援的时间窗口）。

实测（跑 10 天，`IRONMIND_LLM=mock`）：

```
第8军 九江 补给 0.16 → 缺粮
第66军 星子 补给 0.10 → 断粮，日损 0.04 千
第29军团 万家岭 补给 0.12 → 断粮，日损 0.03 千
```

部队列表里直接标成 `断粮·6.8 千 固守`（红字）/ `缺粮·…`。
以前这些数字只在快照里，玩家看不到——于是"我的兵为什么打不动"无解。

## 4 覆灭阈值顺手修了一个 bug

老口径是"兵力不足 1 千 = 全军覆没"，这条只在战斗结算里跑，看起来没问题。
但这次要加"饿死也能触发覆灭"，就得把它挪成全局扫描（`sweep_ended`），
一挪就露馅了：**空军一个飞行团本来就只有 800–1500 人**，
按 1 千判"全歼"，开战第一天整个空军就没了。

改成 **200 人**（`WIPED_OUT`）。900 人的残部仍然是师，番号还在。

## 5 战报要走路（新）

以前所有战报**即时**进日志，等于长官部在全图每个连部都架了电台。
现在 `World.in_transit: Vec<(送达 tick, Event)>`：

- `report_delayed(delay, kind, text, side)`：delay 取
  `comms.report_delay() = transmission + staff`（本模块 = 1 天）；
- 事件里的 `tick` 记的是**发生日**，不是送达日——你看到的日期是事发那天，
  只是今天才收到；
- 每个 tick 末尾 `flush_in_transit()` 把到期的事件放进日志。

覆盖面：编制变动（覆灭/殉国/整编）、断粮、被全歼。
**没有走邮路的**：战斗与易手（战场上看得见的事，即时合理）、
将领请示与回电（本来就是服务端另外的一套延迟）。

> 顺带修了个 off-by-one：`flush` 用的是 `tick + 1`，因为 tick 要到
> 这一步末尾才自增。不 +1 的话 delay=2 的电报永远慢一天。

## 6 测试（`crates/sim-core/tests/supply.rs`，5 个）

1. 干净补给线上的前线拿得到补给（>0.4）；
2. 敌纵队插到中转省 → 前线补给腰斩（<50%）；
3. 断粮十天掉兵、但不会饿光，且战报是**本方内部消息**；
4. 900 人的残部不判覆灭，100 人的空架子判；
5. 电报按天到达，事件日期记的是发生日。

## 7 还没做

1. **铁路与水道运力**：`supply_throughput` 现在是省上的一个常数。
   南浔铁路是这场战役的命脉，应该有独立的一层（铁路被打断 → 运力骤降），
   而且**水路补给**在 BFS 里是被直接跳过的（`Terrain::Water` continue）。
   日军的长江补给线现在完全没有体现。
2. **弹药与油料分离**：现在只有一根"补给"标量。炮兵没炮弹、坦克没油
   都应该单独算，否则"补给 0.4"说不清到底缺什么。
3. **就地征发有限度**：敌省固定 0.5，反复驻扎应该把地方吃空（对民力有代价）。
4. **包围圈判定**：现在断供靠"补给线上有敌人"。真正的合围（所有邻省都是敌军）
   应该额外加一层——万家岭围歼战的核心就是这个。
