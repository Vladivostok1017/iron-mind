# 模块开发手册

> 这是**内容的全部契约**。引擎只提供框架：地图、编制、将领、规则、结局全部由模块声明。
> 读完这份文档，你不需要写一行 Rust 就能做出一个战役。
>
> 字段名、默认值、校验码以 `crates/sim-content/src/model.rs` 和 `validate.rs` 为准；
> 两者不一致，以代码为准，并请报 bug。

---

## 0 三十秒版

一个模块 = 一个目录，四个 JSON。**不需要写代码、不需要编译**。

```
mymod.imod/              ← 目录名随便起，.imod 只是约定，不是压缩包
├─ module.json           元数据（这是什么战役、谁在打、敌方统帅是谁）
├─ scenario.json         战役定义（几天、种子、通信、规则、结局）
├─ map.json              省份、地形、邻接、补给源
├─ oob.json              部队：番号、兵力、位置、将领
└─ provinces_geo.json    （可选）真实省界多边形，没有就用抽象多边形
```

做完之后，在游戏里「新的战役 → 导入模块…」选这个目录就能玩；
作者自己调试用 `cargo run -p sim-testbed -- --module 路径`。

> **`.imod` 不是 zip。** 引擎读的是目录。旧文档写"压成 zip 改后缀"，那是错的，
> 压过之后就加载不了——目录名带 `.imod` 只是为了让它在文件管理器里像个整体。

---

## 1 最小可加载模块

模块有两种形态，**内容完全一样**，读出来的世界逐位一致：

| 形态 | 长什么样 | 什么时候用 |
|---|---|---|
| **目录**（开发形态） | `mymod.imod/` 文件夹，里面四个 json | 写模块时用。能 git diff、能热重载、改一行存盘就生效 |
| **压缩包**（发布形态） | `mymod.imod` 单个文件（本质是 zip） | 发布/分发时用。一个文件能下载、能当附件、能双击导入 |

> `.imod` 早期只是**文件夹后缀**，那是把扩展名当目录标记用：发布时只能再套一层 zip，
> 玩家拿到 `xxx.imod.zip`，解压出来才是模块；"导入模块"还要在一堆文件夹里点对那一层。
> 现在它是一个真 zip：成员是 `module.json` / `map.json` / `oob.json` / `scenario.json`
> （可选 `provinces_geo.json`），**放在包的根部**，不要多套一层目录。
>
> 目录形态**永久支持**——作者开发时必须能改文件、能看 diff。

打包一条命令（引擎仓库）：

```powershell
pwsh -File tools\package.ps1 -Modules 路径\你的模块仓库
# 产出 dist\mymod-v0.1.0.imod（单个文件，32 KB 左右）
```

导入：游戏里「新的战役 → 导入 .imod」选那个文件；或者直接丢进 `modules\` 目录再重启。

四个文件都写全，就能通过校验。复制成新目录、改个 `id` 就是你的模块。

**module.json**

```json
{
  "id": "org.yourname.mymod",
  "name": "我的战役",
  "version": "0.1.0",
  "author": "你的名字",
  "description": "一句话说明。会显示在首页的战役卡上。",
  "engine": { "min": "1.0.0" },
  "content_schema": 1,
  "sides": [
    { "id": "cn", "name": "守军" },
    { "id": "jp", "name": "进攻军" }
  ],
  "playable_side": "cn",
  "scale": "theater",
  "domains": ["land"]
}
```

`cn` / `jp` 只是**这段示例起的名字**。想两边都能玩就再加
`"playable_sides": ["cn", "jp"]`，首页就会出现两个按钮（见 §2.1）。

**map.json**（三个省一条线）

```json
{
  "bbox": [115.9, 29.0, 116.3, 29.6],
  "projection": "wgs84",
  "provinces": [
    { "id": 0, "name": "甲", "terrain": "plain", "owner": "jp",
      "supply_source": true, "neighbors": [1], "lon": 116.0, "lat": 29.5 },
    { "id": 1, "name": "乙", "terrain": "hill", "owner": "cn",
      "neighbors": [0, 2], "lon": 116.1, "lat": 29.3 },
    { "id": 2, "name": "丙", "terrain": "urban", "owner": "cn",
      "supply_source": true, "neighbors": [1], "lon": 116.2, "lat": 29.1 }
  ]
}
```

**oob.json**

```json
{
  "units": [
    { "id": "jp.1", "name": "第1联队", "side": "jp", "strength": 3.0,
      "position": 0, "stance": "attack", "effectiveness": 1.4, "supply_reach": 0.45 },
    { "id": "cn.1", "name": "第1师", "side": "cn", "strength": 8.0,
      "position": 2, "stance": "defend", "effectiveness": 1.0, "supply_reach": 0.12 }
  ]
}
```

**scenario.json**

```json
{
  "id": "scen.mymod",
  "name": "我的战役",
  "start_date": "1938-07-26",
  "days": 30,
  "seed": 1,
  "comms": { "preset": "radio" }
}
```

验证：

```powershell
cargo run -q --release -p sim-testbed -- --module 路径\mymod.imod --ticks 30
```

跑通就说明数据合法。`--units` 看每 15 天的部队状态，`--trace 第101师团` 逐 tick
打某个单位的位置序列（"敌人怎么跑到我后方去了"这类问题只能看时序，不能看快照）。

### 开发循环：改完存盘就重载

做模块最耗人的不是写数据，是"改一行 → 手动导入 → 手动点一天 → 看结果"这个循环。
开发循环的工具在 **SDK 仓库**（`../iron-mind-sdk`）：引擎出货的二进制里不放开发行为，
作者工具也不该混进玩家安装包。它只通过引擎的公开接口驱动内核，不含引擎代码。

```powershell
cd ..\iron-mind-sdk
node imdev.mjs --module ..\nanxun-1938\nanxun_1938.imod
```

它会起内核并**盯着模块目录**（`module.json` / `scenario.json` / `map.json` /
`oob.json` / `provinces_geo.json`）：

- 你一存盘，内核就重载模块、回到第 0 日，控制台打一行 `[重载] 第 0 日 · 87 省`；
- 开着的游戏页面会在 3 秒内自己换地图（省界、模块列表一起刷），不用刷新
  ——机制是内核把"世界代号" `generation` 加一，前端轮询 `/api/llm` 看到变了就重拉；
- **存了一半的坏 JSON 不会毁掉现场**：加载失败只打印错误，继续用旧世界，
  改完再存一次就重载。

两条注意：重载会**清空命令流和电报**（旧命令在新数据上重放没有意义），
所以这是开发工具，不是"换剧本接着打"。要保住进度请用存档。

**本文档留在引擎仓库**，不搬进 SDK：规范和 `validate.rs` / `migrate.rs` 必须住在一起，
否则文档和实现必然漂移。SDK 只放工具。

## 2 module.json

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 全局唯一，反域名。**决定导入时的目录名**（取最后一段） |
| `name` | 是 | 显示名。首页战役卡、顶栏都用它 |
| `version` | 是 | 模块自己的版本 |
| `description` | 否 | 首页战役卡的正文。写清"这是哪一仗、你扮演谁" |
| `author` | 否 | 署名 |
| `engine.min` | 是 | 需要的最低引擎版本，如 `0.10.0` |
| `engine.max` | 否 | 最高支持版本。不填就一直不管 |
| `content_schema` | 否 | 模块格式版本，当前 `1`。高于引擎支持值会报 `meta.future_schema` |
| `sides` | 否 | **这一仗有哪两方、各自叫什么**。见 §2.1。不写就是老样子（`cn`/`jp`，显示名同 id） |
| `playable_side` | 否 | 玩家默认操作的一方（`sides` 里的 id），默认 `sides` 的第 1 个 |
| `playable_sides` | 否 | 允许玩家挑哪几方，如 `["cn","jp"]`。**写了才出现"选阵营"** |
| `scale` | 否 | `theater`（默认，约 35 km/省）/ `front`（正面/方面军，约 5–10 km/省，12–120 省）/ `battle` / `siege` / `naval`。只影响校验严格程度 |
| `domains` | 否 | `["land","naval","air"]` 的子集。声明了却没有对应单位会报错/告警 |
| `hq` | 否 | **非玩家阵营的统帅部（AI 玩家）**，见 §2.2。写 `sides[].hq` 更精确 |

### 2.1 `sides`：阵营是内容，不是引擎的常识

引擎内部只有 **A 方 / B 方** 两个位置，它不知道这一仗是谁在打。
`cn`/`jp` 也不是它认识的词——那只是老模块的写法，因为**没有声明时的默认值**是
`["cn","jp"]`（为的是让 1.0 之前的模块还能加载）。

```json
"sides": [
  { "id": "cn", "name": "第九战区" },
  { "id": "jp", "name": "第11军" }
]
```

- 第 1 个 = A 方，第 2 个 = B 方。`oob.json` / `scenario.json` / `map.json` 里
  引用的是 `id`，不是"第几方"。
- `name` 是**给人看的**：首页按钮（"作为第九战区"）、顶栏（"指挥第11军"）、
  战报抬头（"第11军攻占 瑞安"）都用它。不写就退回 `id`。
- id 随你起：`us`/`de`、`rome`/`carthage`、`north`/`south` 都行。
- 只能两方。三方以上引擎还没有（这是明确的限制，不是遗漏）。

**换一场仗就换一套名字。** 引擎里没有"国军""日军"这两个词，
`crates/sim-core/tests/no_nation_names.rs` 会盯着这件事——它扫引擎源码，
代码里出现具体国名/番号就测试失败（注释里举例是可以的）。

### 2.2 什么是 `hq`

"对面也有一个玩家"的实现：一个有目标、有性格的 LLM 指挥官，会按自己的方针
给自己的部队下命令——走的是**和玩家一样的通道**（电报 → 将领判断 → 执行），
所以将领照样可以不听他的。

```json
"sides": [
  {
    "id": "cn", "name": "第九战区",
    "hq": {
      "name": "薛岳", "title": "第九战区第一兵团总司令",
      "persona": "粤军出身，一辈子在打机动防御……",
      "agenda": "把日军放进来再掐断；最怕各部各自后撤。",
      "objectives": ["依托山地逐次抵抗", "守住德安—永修一线", "抓住孤军深入的一路围歼"]
    }
  },
  {
    "id": "jp", "name": "第11军",
    "hq": {
      "name": "岡村寧次", "title": "第11军司令官",
      "persona": "情报参谋出身……不爱为抢功而分兵。",
      "agenda": "打通南浔线，但更怕师团被各个击破。",
      "objectives": ["沿铁路南下夺取德安", "保护长江水路补给线", "避免孤军深入"]
    }
  }
]
```

| 字段 | 说明 |
|---|---|
| `name` / `title` | 谁、什么职务。会出现在战报与指挥链里 |
| `persona` | 他是什么人、怎么用兵。决定他的判断风格 |
| `agenda` | 他的作战意图（**方针**，不是"我怕什么"）。决定他往哪儿使劲 |
| `objectives` | 战役目标，按优先级。每次开会都喂给他 |

**为什么要按方写**：玩家能挑阵营，AI 就得替**另一边**指挥。玩家玩第九战区时
AI 是岡村，玩家玩第11军时 AI 就得换成薛岳——一个模块只写一个 `hq` 的话，
换边之后 AI 会拿敌将的性格指挥我军。顶层的 `hq` 仍然有效（老模块就靠它），
它在 `sides[].hq` 缺席时兜底。

不写任何 `hq`，对面就只有将领各自为战。**写它，敌军才会像一个整体在打仗。**

### 2.3 两边都能玩

```json
"playable_sides": ["cn", "jp"]
```

写了这一段，首页这张战役卡上就会出现两个按钮——`作为{sides[0].name}`
和 `作为{sides[1].name}`。点哪个就打哪一边：

- **模拟完全一样。** AI 不因为"你在哪边"改变任何规则；变的只是
  你能看到什么（情报视图）和能指挥谁。
- **AI 接手另一边。** 你选 `jp`，AI 就用 `cn` 的 `hq` 替你对面下决心；
  你选 `cn`，AI 就用 `jp` 的。两个 `hq` 都写全，换边才不会串戏。
- **换阵营 = 重开一局。** 两边的命令流不能混着重放，所以切换时清掉命令、
  电报、公文。存档里记着当时是哪一方，读档会恢复。
- **战报跟着换称呼。** 引擎只写"第几方攻占某地"，界面按你的 `sides`
  换成"第11军攻占 瑞昌"。
- **不写 `playable_sides`** 就只有 `playable_side` 一方可玩（1.0 的行为）。

只有一个番号、一句台词的战役也可以只给一方玩。两边都写，是让人能
"换个立场看同一场仗"——这是这个引擎和普通战棋最大的不同。

## 3 map.json

```json
{
  "bbox": [115.7, 28.6, 116.3, 29.9],
  "projection": "wgs84",
  "provinces": [ { "...": "见下" } ]
}
```

| 顶层字段 | 说明 |
|---|---|
| `bbox` | 西/南/东/北。用于地图自动取景，不写也能跑 |
| `projection` | 目前只支持 `wgs84`（等距圆柱投影），不写当 `wgs84` |

### 省份字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | **必须 0..n-1 连续**，引擎按索引访问 |
| `name` | 是 | 显示名。战报里点名靠它，也是将领认地名的唯一依据 |
| `terrain` | 是 | `plain` / `hill` / `mountain` / `marsh` / `water` / `urban` |
| `owner` | 是 | `cn` / `jp`，不能留空（`map.unowned_province`） |
| `neighbors` | 是 | 邻接省 id，**必须双向**，最多 12 个 |
| `supply_source` | 否 | 补给源。**每一方至少一个** |
| `rail` | 否 | 有铁路/公路干线，补给沿它传几乎不掉（×0.95），**地图上会画成铁轨** |
| `airbase` | 否 | 机场。空军从这里起飞：**出击半径按机场算**（可多个机场取并集）。模块里一个机场都没写 = 旧行为（射程按飞机自己位置）；写了但本方没有机场 = 出击效率减半 |
| `port` | 否 | 港口。海运补给在港口"装卸"：从港口进水道（或从水道进港口）的损耗从 0.85 降到 0.95 |
| `station` | 否 | 车站名（如 `"九江站"`）。**铁路上的转运点**：补给经过它会被"重新装载"到 0.9，于是这条线能一站一站往前推。只在「上一段也是铁路 + 这段没被炸断 + 没有敌军踩在上面」时生效。地图上画一个双圈站点符号 |
| `supply_throughput` | 否 | 0-1，默认 1.0。这个省的转运能力，越小越拖后腿 |
| `fort` | 否 | 0-5 初始工事 |
| `victory_points` | 否 | 要点权重，目前只做标注 |
| `prototype` | 否 | 地形原型，目前只做标注（见下） |
| `positions` | 否 | 省内阵地，不写自动生成一个 |
| `lon` / `lat` | 否 | 经纬度。不写就摆不好地图（前端靠它定位与取景） |
| `elev` / `relief` | 否 | 平均海拔、相对高差（米）。**模拟不读**，只用来解释"为什么这里是山地" |
| `note` | 否 | 出处备注。值得写 |

### 地形与地形原型

| 地形 | 防御乘数 | 说明 |
|---|---|---|
| `plain` | 1.0 | |
| `hill` | 1.2 | |
| `mountain` | 1.4 | 行军慢、有非战斗减员 |
| `marsh` | 1.1 | |
| `water` | 1.6 | 只有海军能进 |
| `urban` | 1.3 | |

工事每级再 +0.15。

`prototype` 是从战场推演里提炼的要点类型，目前只做标注：
`ridge_line` / `river_ridge` / `pocket` / `isolated_height` / `village_node` /
`road_cut` / `city_gate` / `beachhead` / `encircle_gap` / `retreat_fan`。

### 阵地（positions）

省是**作战**尺度（约 35 公里），阵地是**战术**尺度（2-5 公里）。
不写 `positions` 就自动生成一个（省名 + 省地形 + 全宽），所以小模块不用管。

```json
{
  "id": 18, "name": "万家岭", "terrain": "mountain",
  "positions": [
    { "name": "张古山", "terrain": "mountain", "width": 0.4 },
    { "name": "扁担山", "width": 0.6 },
    { "name": "哔叽岭", "width": 0.5, "fort": 2 }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `name` | 阵地名。出现在单位牌、悬停卡、战报里 |
| `terrain` | 不写就沿用省地形 |
| `width` | **展开正面 0.2-1.0**。每方战力先按 `width × 40 千人` 封顶，多出来的只能当预备队。窄阵地 = 只能硬啃 |
| `fort` | 初始工事 0-5，之后靠「筑工事」命令提升（三日一级） |

判断标准：**省的数量由行军速度定，阵地的有无由战场形态定。**
两个地名相距不到 10 公里，做成两个省会打不出"反复易手"，做成一个省的两个阵地才有意义。

### 地图的四条硬约束（都直接影响玩法）

1. **一个省每方最多 3 个地面单位**（`STACK_LIMIT`）。省太少 → 部队挤成一堆。
2. **邻接有敌军时不能占领**。所以"绕过守军去涂色"不成立。
3. **地面部队不能在空省里穿行深入敌后**：进入敌占省要求这一省挨着本方控制区
   （或者省里有敌军——那是进攻，不拦）。想深入就得一省一省占下来。
4. **补给要从补给源沿己方省份走得到**，否则那个省里的部队直接断粮。

→ 所以地图必须留出**可以迂回的省**，而不是一条从九江到南昌的直线。

## 4 oob.json

```json
{
  "units": [
    {
      "id": "jp.106",
      "name": "第106师团",
      "side": "jp",
      "parent": "第11军",
      "kind": "infantry",
      "strength": 16.0,
      "position": 0,
      "stance": "attack",
      "effectiveness": 1.5,
      "supply_reach": 0.45,
      "estimated": true,
      "reform_days": 20,
      "reform_ratio": 0.5,
      "commander": {
        "name": "松浦淳六郎",
        "title": "第106师团长",
        "obedience": 0.8,
        "initiative": 0.5,
        "aggression": 0.6,
        "caution": 0.55,
        "persona": "熊本人，做过第6师团旅团长，熟悉山地战……",
        "agenda": "第106是新编师团，他急于一战立威，敢把部队往深山里带。"
      },
      "note": "史实约 1.6 万人"
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 模块内唯一 |
| `name` | 是 | 显示名。**玩家发电报就是点这个名字**，写番号不是人名 |
| `side` | 是 | `cn` / `jp`，**双方都必须有单位** |
| `strength` | 是 | **千人**。`16.0` = 一万六千人；写 `16000` 就是一千六百万 |
| `position` | 是 | 所在省 id |
| `kind` | 否 | `infantry`（默认）/ `armor` / `air` / `naval` |
| `stance` | 否 | `attack`（默认）/ `defend`，见下 |
| `effectiveness` | 否 | 战斗力系数，默认 1.0 |
| `supply_reach` | 否 | 补给延伸能力 0-1，默认 0 |
| `parent` | 否 | 上级番号，只做展示 |
| `estimated` | 否 | 是否推断值。`false` 表示有确切记载 |
| `reform_days` | 否 | 覆灭后多少天可在后方重新成军。**0 = 不可重建** |
| `reform_ratio` | 否 | 重建后补到满编的几成（0.5 = 五成） |
| `recon_radius` | 否 | 航空侦察半径（跳数）。仅 `air` |
| `strike_power` | 否 | 空中打击强度。仅 `air`，0 表示只侦察 |

### 引擎自带的示例模块（`content/scenarios/`）

| 目录 | 演示什么 |
|---|---|
| **`tutorial.imod`** | **教学关**：5 省、一条铁路、一座桥。屏幕上有一张卡片按你的真实操作往下走（选部队→发电报→推进一天→读战报→看补给），走完五步就会玩了。首页「教程 · 三分钟」直接进 |

| **`demo_nodes.imod`** | **后勤与空海机制**：铁路 + 两个车站、双方各一个机场、两个港口、一条可封锁的江面、7 个多阵地省。10 省、8 支部队，专门用来看清 1.6.x 这批改动 |

| `siege_tianjiazhen.imod` | 攻坚/要塞：窄阵地与工事 |

`demo_nodes` 里值得上手试的四件事：

1. **车站转运**：北站 → 货场 → 桥北，补给在车站"重新装载"，能一站一站推到桥头；
2. **机场射程**：把北岸飞行队拉到北站（有机场）才够得着南岸，否则射程从它自己的位置算；
3. **封锁**：让江防舰队带「封锁」命令停在江心水面 → 江南码头的海运补给被掐断；
4. **窄阵地**：桥北的「桥头堡」只有 0.4 展开宽度，塞不下两个团，多的只能当预备队。

### 空军与海军的命令

亲自指挥下，兵种决定能下什么命令（`fireVerb` 按 `kind_code` 选）：

| 兵种 | 命令 | 说明 |
|---|---|---|
| 空军 | **侦察** `recon` | 只出情报（`recon_radius` 照常生效），**不投弹、不损耗**。想"先看看再打"就用它 |
| 空军 | **出击** `advance` | 指定目标省投弹；不指定则由引擎挑最值得炸的一个（优先自己地面部队在场的仗） |
| 海军 | **封锁** `blockade` | 切断**敌方沿岸省的海运补给**（陆路不受影响）。同一片水域多支舰队取并集 |
| 海军 | **推进** `advance` | 在水道间移动 |
| `commander` | 否 | 将领。不写就是完全服从的默认将领 |
| `note` | 否 | 出处备注 |

### stance：为什么防守方不会自己跑掉

AI 默认"邻接有敌就进攻，没有就朝最近敌人推进"。给防守方也套这套逻辑，它会
**主动放弃阵地去迎敌**——兵力再多也守不住，因为守军全在路上。

| 值 | 行为 |
|---|---|
| `attack`（默认） | 邻接有敌省就进攻；没有就朝最近的敌人推进。适合进攻方 |
| `defend` | 守在原地、吃地形与工事加成；反攻交给玩家（或将领抗命） |

**引擎不认国家，只认姿态。**"这一方该守"是史实知识与玩法设计，属于模块。

### strength 的口径（最容易写错的一处）

这条踩过一个大坑：最初把国军的军写成 8–15 千，比日军一个师团还少，于是
"中国兵多、装备差"这个基本事实在数据里是**反的**——国军比日军还少，怎么打都输。

史实近似值（推演用）：

| 单位 | 实有兵力 |
|---|---|
| 国军一个师 | 约 7–9 千（1938 年实编，缺额严重） |
| 国军一个军（2–3 师） | 约 15–27 千 |
| 日军一个常备师团 | 约 20–25 千 |
| 日军一个支队/旅团 | 约 4–6 千 |

所以**国军总兵力应当明显多于日军**（南浔线模块：159.8 千 vs 96.5 千 = 1.66 倍），
代差靠 `effectiveness` 拉开。校验器在"可玩方兵力少于敌方"时报
`balance.lopsided`——那不是引擎的平衡表，是给作者的体检提醒。

### effectiveness 与 supply_reach：两把不同的刀

| `effectiveness` | 建议 |
|---|---|
| 日军常备师团 | 1.4–1.7 |
| 日军支队 | 1.3–1.5 |
| 国军中央军 | 0.9–1.15 |
| 国军地方部队 | 0.6–0.8 |

| `supply_reach` | 建议 |
|---|---|
| 日军（汽车 + 铁路 + 水路） | 0.45–0.50 |
| 国军中央军（人力挑运） | 0.14–0.18 |
| 国军地方部队 | 0.08–0.12 |

`effectiveness` 是装备与训练的代差；`supply_reach` 是"能把补给缺口补上多少"。
**别让双方共用一套补给衰减**——那等于抹掉了机械化部队对人力挑夫的优势。

⚠️ `effectiveness` 有阈值效应：调到某个点以下进攻方全灭，调上去就碾压，中间过渡很窄。
这是战斗模型还浅导致的，别指望靠调参做出拉锯。

### 将领：四个数字 + 三段文本

| 字段 | 含义 |
|---|---|
| `obedience` | 服从度。越低越可能抗命、打折扣 |
| `initiative` | 主动性。越高越可能自行改变目标 |
| `aggression` | 进攻倾向。高的人愿意强攻，低的人偏好稳守 |
| `caution` | 谨慎。高的人先算退路，强攻时留的预备队多 |
| `title` | 职务。只给 LLM 看 |
| `persona` | 人物志：出身、经历、用兵习惯。只给 LLM 看 |
| `agenda` | **他怎么打、怎么报**——报功口径、投入脾气、敌情滤镜。只给 LLM 看 |

四个数字参与模拟（进 `state_hash`）；三段文本**不参与模拟**，只在接模型时进提示词。
没有它们，模型只能按四个小数臆想一个军官；有了它们，它才会自己想到
"这是临时编成的师团，装备最差，不能当消耗品用"。

写法建议：

- `persona` 写"**他是怎么打仗的人**"；
- `agenda` 写"**他因此怎么说话**"——战果往哪边夸、伤亡缩不缩水、敌情估高还是估低。

**不要写"他为什么可能不听你的"。** 保存实力、怕部队打光、不愿替友军填坑，那是军阀政治的逻辑，
发生在全国层面；正面战场上全连殉国是常态，没有师团长会拿"我部队会打光"当理由递上去。
写成那样，模型就会演一个不肯打仗的人。

完整规则、正反例对照与自检方法见 **[`docs/26-模块作者-AI提示词指南.md`](../docs/26-模块作者-AI提示词指南.md)**。

三条硬约束：将领只能改方向、不会投敌；抗命只朝"更保守"或"更激进"偏；
`obedience = 1.0` 的将领永不抗命。

### 二次整编

部队覆灭（兵力打到 200 人以下，或战斗中被全歼）不会从编制簿上消失：

- `reform_days > 0` → 过这么多天在本方**补给源**重新成军，兵力补到 `reform_ratio`；
- `reform_days = 0` → 这个番号就没了（史实上有些部队打光就再没有了）。

将领会殉国/被俘（引擎掷骰），殉国的将领跟着番号一起进编制簿。

## 5.5 机制开关（preview）· 1.0 起默认全开

这四个机制原来是"模块声明才生效"的预览版。**1.0 把它们并回主线**：默认开启，
是引擎的正式基线。理由很直接——密集正面、弹药油料、断补给、派系，这些不是花活，
而是"能不能表达真实战役"的前提；把它们关在开关后面，等于把大部分真实战场
挡在引擎之外。

想退回旧行为的模块在 `scenario.json` 里**显式关掉**：

```json
"preview": {
  "ammo_fuel": false,   // 关掉弹药与油料
  "rail_damage": false, // 关掉铁路被炸/抢修
  "politics": false,    // 关掉派系与人事
  "front_line": false   // 关掉连续正面模型（战役级地图可能需要）
}
```

三条规则：

1. **不写 = 全开。** 新模块什么都不用写，拿到的是正式基线。
2. **四个开关互相独立。** 只关 `front_line` 不影响弹药油料。
3. **关掉了会挂牌子。** 界面右上角显示"经典模式 · 连续正面"，让玩家知道
   自己玩的不是默认规则——否则"阵地拿不下来"会被当成 bug 报上来。

### 默认值跟着**地图尺度**走，不是一刀切

同一个"邻接有敌不准占领"，在不同粒度上是两件事：

- 35 km/省 的战役图：一个省是一个"**区**"，侧翼和后方是真实存在的
  → 占领要求清空邻省才符合这个时空粒度（防穿插）。
- 5–15 km/省 的正面图：一个省是一个"**阵地**"，把它打空就等于拿下了
  → 四邻皆敌是常态，不该因此冻住战线。

所以：

| `scale` | `front_line` 默认 | 其余三项 |
|---|---|---|
| `theater`（≈35 km/省） | **关**（粗口径） | 开 |
| `naval` | 关 | 开 |
| `front` / `battle` / `siege`（5–15 km/省） | **开**（连续正面模型） | 开 |

写 `"preview": { "front_line": true/false }` 可以覆盖任一方向的默认值——
但先把 `scale` 写对，通常就不需要这一段了。`scale` 不只是个标签，它决定语义。

> 官方战役**南浔线 1938** 什么都没写：它是 `scale: "theater"`，于是自动拿到粗口径。
> 实测 77 日：国军 56 省 / 日军 31 省，**九江、德安失守，南昌还在手里**——
> 与史实（1938 年 10 月德安失守、南昌直到 1939 年 3 月才陷）大致吻合。
> 如果给它打开连续正面模型，77 日内南昌会丢：那是**尺度标错**的症状，不是平衡问题。

对应的字段（全部可选，全部只在开关打开时才有意义）：

| 开关 | 新增字段 | 位置 | 作用 |
|---|---|---|---|
| `ammo_fuel` | `ammo`（0-1，默认 1） | `oob.json` 每个单位 | 开局弹药基数 |
| | `fuel`（0-1，默认 1） | 同上 | 开局油料基数 |
| | `fuel_burn`（0-1） | 同上 | 每动一步的油耗；不写按兵种给（步兵 0、装甲 0.12、海空军 0.15） |
| `politics` | `factions` | `oob.json` | 派系表：`id` / `name` / `side` / `weight` |
| | `commander.faction` | `oob.json` 将领 | 这个将领属于哪个派系 id |

铁路被炸不需要新字段：它作用于 `map.json` 里已经声明的 `rail: true` 那些省。
同理，`station` 也是普通字段 —— 但它只在铁路还在的时候有用：**炸断一段，这条线上的
车站转运就全废了**，这也是"炸路"真正的战略意义（不只是让补给掉一点）。

### `front_line`：连续正面模型

一个省 5–10 公里、战线连续的战役（淞沪、南京、台儿庄、长沙）会遇到三处只在
"密集正面"上暴露的语义问题。`"preview": { "front_line": true }` 把三处一起换掉：

| 原来的口径 | 打开后 | 为什么 |
|---|---|---|
| 邻省都不在我手里 → 被围（补给归零） | 邻省里有我的**地面部队**也算没断 | 战线连续时每个突出部都四邻皆敌，进攻方会自己先饿死 |
| 占领要求目标省**和所有邻省**都没有敌人 | 只看目标省内有没有敌人 | 一个 1 千人的残部就能冻住整条战线，"逐个打穿阵地"表达不出来 |
| 超出 `width×40` 的战力硬截成相等 | 超出部分按 30% 计入 | 硬截断会把双方战力拉平，强者优势归零（实测 effectiveness ×3 后自身伤亡率一动不动） |

默认开启（1.0 起）。战役级地图（35 公里/省）如果发现战线塌得太快，可以在这个模块里写 `"front_line": false` 退回旧口径。

## 5.6 迟到番号（arrivals）

**没有哪一场战役是第一天全员到齐的。** 淞沪的第10军第 84 天才在金山卫登陆，
南浔线的 74 军/桂系/川军也是中途到场。以前只能把部队事先摆在滩头上，
等于把"登陆"变成"一开始就在那儿"。

```json
// scenario.json
"arrivals": [
  { "day": 48, "unit": "jp.9",  "province": "狮子林" },
  { "day": 84, "unit": "jp.6",  "province": "杭州湾滩头" }
]
```

| 字段 | 说明 |
|---|---|
| `day` | 战役第几日到场（0 = 开局就在场） |
| `unit` | `oob.json` 里的单位 `id` |
| `province` | 到场省**名**，必须和 `map.json` 的 `name` 一致 |

也可以写简写：在 `oob.json` 的单位上加 `"arrives_on": 48`，省名取它自己的 `position`。

语义（都不 panic、都不瞬移）：

- 到场前这支部队**对全世界不存在**：不参战、不占堆叠、不进情报、不计入总兵力；
- 到场当天即可参战（史实里第10军登陆当天就投入了战斗）；
- 登陆场丢了或堆叠满了 → **顺延一天**，明天再试（部队在海上等着）；
- 到场没有写入状态哈希，回放能复现"第 84 天在金山卫登陆"；
- 不写 `arrivals` 的模块 = 全员开局在场，行为与以前完全一致。

打开方式（复制一个现有模块改最省事）：

```powershell
# 以 demo 为例，只加 scenario.json 里的一段，其余不动
"preview": { "ammo_fuel": true }
```

开了之后，控制台会打一行 `预览版：ammo_fuel`，界面右上角出现"预览版"角标。
没有这一行说明**没开**（字段拼错、放错文件都会这样），用严格模式跑一次就知道：

```powershell
cargo run -q --release -p sim-testbed --features sim-content/strict -- --module 路径\mymod.imod
```

### 现成的例子：`content/scenarios/preview_probe.imod`

引擎自带一个 4 省的小模块，三个开关全开，专门用来看这四个系统各自的样子：

- 空军（`recon_radius: 3`）发一封电报"派飞机炸掉东营的铁路" → 一两天后铁路坏一级，
  再炸两轮就断（战报里会有"铁路被炸坏一段（1/3）"）；
- 战车队开局只有四成油（`fuel: 0.4`）→ 走两趟就缺油，走不动；
- 两个派系（中央系 0.7 / 地方系 0.35）+ 三个带兵将领各属一派 →
  右键部队列表里的部队可以撤换主官，撤完那一派的影响力会掉；
- 右上角"回放"按钮 → 拖时间轴回看前面几天（第 1 日、第 3 日……），
  看的是**按命令流重算出来的世界**，不是录像。

它不是给玩家玩的战役，是给作者看的对照物：想做一个开预览机制的模块，
拿它当模板改就行。

## 6 结局（endings）

引擎不认识"天炉""苦撑"这些词。它只认三件事：**指标、比较、优先级**。
所以结局完全由内容决定：同一套引擎可以描述 1938 年的南浔线，也可以描述别的战役。

```json
"endings": [
  {
    "id": "hold_the_line",
    "name": "南浔线未破",
    "text": "日军未能打通南浔线，德安仍在手里……",
    "priority": 10,
    "at_end_only": true,
    "require": [
      { "metric": "provinces", "side": "cn", "cmp": "ge", "value": 50 },
      { "metric": "holds_province", "side": "cn", "cmp": "ge", "value": 1, "province": "德安" }
    ]
  },
  {
    "id": "line_collapsed",
    "name": "南浔线失守",
    "text": "德安易手，南昌门户洞开……",
    "priority": 5,
    "at_end_only": false,
    "require": [
      { "metric": "holds_province", "side": "jp", "cmp": "ge", "value": 1, "province": "德安" }
    ]
  }
]
```

| 字段 | 说明 |
|---|---|
| `id` / `name` / `text` | 结局标题与正文。正文是给玩家看的**历史评价**，不是比分 |
| `priority` | 越小越先判。多条同时命中时取优先级最高的一条 |
| `at_end_only` | `true`（默认）只在战役期满时判；`false` 每天都可以提前触发（崩盘、速溃） |
| `require` | 全部满足才算命中。**留空 = 永远命中**，会被跳过 |

### 判定子句（Clause）

```json
{ "metric": "provinces", "side": "cn", "cmp": "ge", "value": 50 }
```

| 字段 | 说明 |
|---|---|
| `metric` | 见下表 |
| `side` | `cn` / `jp`。`holds_province` 必须写 |
| `value` | 阈值。**`holds_province` 必须写 `1`**：它是 0/1 量纲，省略值 + 默认 `ge` 会变成 `x >= 0`，**恒成立**——那条结局会在第 1 天命中并把战役判死（引擎现在缺省按 1.0 处理，并对恒真子句报 `ending.clause_tautology` 警告） |
| `cmp` | `ge`（默认）/ `gt` / `le` / `lt` |
| `value` | 阈值 |
| `province` | 仅 `holds_province` 用：**省名，必须和 map.json 里的 `name` 完全一致** |

| metric | 含义 |
|---|---|
| `day` | 当前天数 |
| `provinces` | 控制省数 |
| `strength` | 总兵力（千） |
| `losses` | 累计损失（千） |
| `units_alive` | 在编单位数 |
| `commanders_lost` | 殉国/被俘的将领数 |
| `holds_province` | 是否控制某省（1/0），配合 `province` |

**写结局的建议**：不要写"你赢了"。写 5–12 条不同走向，让同一个局面在不同判断下
落到不同的历史上。这是这个引擎和别的战争游戏最大的不同。

## 7 自定义规则（rules）

模块能力最强的一块：在 `scenario.json` 里声明规则，引擎按固定时机执行。
**不需要写代码，不需要改引擎。**

```json
"rules": [
  {
    "id": "armor_bogged_in_marsh",
    "phase": "post_movement",
    "priority": 10,
    "when": { "all": [ { "terrain": "marsh" }, { "unit_kind": "armor" } ] },
    "then": [
      { "modify_strength_pct": -0.02 },
      { "modify_morale": -0.05 },
      { "log": "装甲部队陷入沼泽，损失惨重" }
    ]
  }
]
```

### 阶段（phase）

| phase | 时机 |
|---|---|
| `pre_supply` | 补给计算之前 |
| `post_supply` | 补给计算之后、整编之前 |
| `post_movement` | 移动之后、战斗之前 |
| `pre_combat` | 战斗解算之前 |
| `post_combat` | 战斗之后 |
| `post_tick` | 整个 tick 结束 |

### 条件（when）

| 写法 | 含义 |
|---|---|
| `{"always": true}` | 总是 |
| `{"never": true}` | 永不（调试用） |
| `{"terrain": "mountain"}` | 所在省是山地 |
| `{"unit_kind": "armor"}` | 单位是装甲 |
| `{"strength_below": 0.35}` | 兵力低于编制的 35% |
| `{"province_owner": "cn"}` | 所在省归 `cn` 方（写你 `sides` 里的 id） |
| `{"side": "cn"}` | **单位本身**属于 `cn` 方（写单向机制用，例如"只有守军缺弹药"就写守军那个 id） |
| `{"in_combat": true}` | 该单位当下**真的在交战**（同省有敌方地面单位）。写"巷战只伤害正在打的部队"，不会给所有驻军按天收税 |
| `{"all": [...]}` | 全部满足 |
| `{"any": [...]}` | 任一满足 |
| `{"not": {...}}` | 取反 |

地形：`plain` / `hill` / `mountain` / `marsh` / `water` / `urban`
兵种：`infantry` / `armor` / `air` / `naval`
阵营：你的 `sides[].id`（老模块不写 `sides` 时是 `cn` / `jp`）

### 动作（then）

| 写法 | 含义 |
|---|---|
| `{"modify_strength_pct": -0.02}` | 按当前兵力百分比增减 |
| `{"modify_morale": 0.05}` | 士气增减（0-1） |
| `{"modify_supply": -0.1}` | 补给增减（0-1） |
| `{"log": "文本"}` | 写一条战报 |

### 三条约束

1. **规则不能有随机**。要随机只能用引擎的确定性随机源——否则回放会崩。
2. **执行顺序固定**：先 phase，再 priority（小的先），最后 id 字典序。**不依赖你写的顺序。**
3. **规则只能调用上面的动作**，不能直接改世界状态。

## 8 通信（comms）

引擎只认**延迟天数**，不认年代。不同时代的模块配不同数值——这是跨时代兼容的核心。

```json
"comms": { "preset": "radio" }
```

| preset | 适用 | `transmission` | `staff` | `order_delay` |
|---|---|---|---|---|
| `courier` | 前电报时代（骑兵传令） | 2 | 1 | 1 |
| `wire_telegraph` | 有线电报（1930 年代） | 0 | 1 | 0 |
| `radio` | 无线电时代 | 0 | 1 | 0 |

不用预设时直接写三个数字：

```json
"comms": { "transmission": 0, "staff": 2, "order_delay": 1 }
```

| 字段 | 含义 |
|---|---|
| `transmission` | 技术传输延迟（天）。电报/无线电是 0，骑兵 2–3 |
| `staff` | 参谋汇总、核实与决策延迟。**这才是 1938 年的真正瓶颈** |
| `order_delay` | 命令逐级下达的额外延迟 |

两条派生量：

- **战报延迟** = `transmission + staff`（情报多久进入你的视野）；
- **命令延迟** = `transmission + order_delay`（你的电报多久到达执行单位）。

> ⚠️ **只有这三个键名有效。** `local_delay` / `adjacent_delay` / `air_delay` 这类
> 按"远近"分档的写法**不存在**——写了会被静默忽略，你拿到的还是默认值。
> （这条踩过：旧版本的手册就是这么写的，照着抄的人以为自己在改延迟。）

**不要用年代名当配置**，只写天数。引擎不认识年代。

## 9 provinces_geo.json（可选：真实省界）

```json
{
  "source": "DataV 行政区划（县界）",
  "simplify": 0.008,
  "polygons": {
    "0":  [[[116.0829, 29.7612], [116.0725, 29.7607]]],
    "18": [[["...每一环都是 [lon, lat] 数组"]]]
  }
}
```

- 键是**省份 id 的字符串**，值是若干条环（外环 + 空洞），每条环是 `[lon, lat]` 数组；
- 有它就用真形状，没有前端退回抽象多边形（所以小模块不用做这一步）；
- 生成脚本：`tools/mapgen/boundaries.js`（南浔线用 DataV 县界，87 个省 345 KB）。

体积参考：**每省约 4 KB**。100 个省 ≈ 400 KB，可以接受；别塞到几 MB。

## 9.5 版本与迁移（引擎对作者的承诺）

`module.json` 里的 `content_schema` 是**模块格式的版本号**。它存在的唯一理由：
引擎的字段以后可能要改，而你的模块不该因此突然坏掉。

引擎给的是**代码级的承诺**，不是文档里的一句话：

| 情况 | 引擎行为 |
|---|---|
| 你的 schema 比引擎旧 | 自动跑迁移器，把旧结构改成新结构。**你什么都不用改**，控制台会打 `迁移：schema 1 → 2` |
| 你的 schema 比引擎新 | 拒绝加载，并说清"要升级引擎还是降 schema" |
| 引擎**缺**这一步迁移器 | 拒绝加载，并点名缺哪一步。这是引擎的 bug，不要改模块去迁就 |
| 迁移器明确拒绝（语义变了，无法自动转） | 拒绝加载，并把"该把哪个字段改成什么"写在错误里 |

只做一件事的保证：**绝不静默用默认值蒙混**。以前字段改名时，旧名字对不上，
serde 用默认值顶上、不报错——作者的地图悄悄变了个样，查一天都查不出来。

### 严格模式：查字段名拼错

作者最常见的错误是**拼错字段名**。普通模式下拼错的字段会被忽略（用默认值），
看起来"能跑但行为不对"。开发时用严格模式，未知字段直接报错：

```powershell
cargo run -q --release -p sim-testbed --features sim-content/strict -- --module 路径\mymod.imod
```

报错长这样：

```
解析失败 scenario.json: unknown field `adjacent_delay`,
expected one of `preset`, `transmission`, `staff`, `order_delay`
```

> 这不是假设：本仓库的南浔线模块就真的带着三个不存在的 `*_delay` 字段
> （旧版手册教的写法），一直是被静默忽略的。严格模式第一次跑就抓出来了。

### `_comment`：JSON 里的注释

JSON 没有注释语法，作者一定会想写点什么。约定：**以下划线开头的键一律当注释丢掉**，
两种模式下都不会报错。

```json
"comms": {
  "_comment": "无线电台：传输秒级，瓶颈在参谋汇总",
  "preset": "radio"
}
```

想真正标注地图与部队的出处，用各省各单位的 `note` 字段——那个会被保留下来。

## 10 校验：加载时会挡下什么

`Error` 级拒绝加载（游戏里表现为"加载失败"），`Warning` 只在控制台提示。

| 代号 | 级别 | 含义 / 怎么改 |
|---|---|---|
| `meta.empty_id` | Error | `module.json` 的 `id` 不能为空 |
| `meta.empty_engine_min` | Error | `engine.min` 不能为空 |
| `meta.future_schema` | Error | `content_schema` 高于引擎支持值 |
| `map.empty` | Error | 地图没有省份 |
| `map.empty_name` | Error | 省份没写 `name` |
| `map.duplicate_id` | Error | 省 id 重复 |
| `map.id_out_of_range` | Error | 省 id 必须 0..n-1 连续 |
| `map.fort_range` | Error | `fort` 超出 0-5 |
| `map.throughput_range` | Error | `supply_throughput` 超出 0-1 |
| `map.neighbor_out_of_range` | Error | 邻接指向不存在的省 |
| `map.self_loop` | Error | 省不能邻接自己 |
| `map.asymmetric_neighbor` | Error | **邻接必须双向**（A 写了 B，B 必须写 A） |
| `map.too_many_neighbors` | Error | 一个省邻接超过 12 个 |
| `map.no_supply_source` | Error | 某一方没有任何补给源 |
| `map.unowned_province` | Error | 有省没写 `owner` |
| `map.owner_orphans` | Warning | 有己方省份从补给源走不到（那里的部队会断粮） |
| `oob.empty` | Error | `oob.json` 没有单位 |
| `oob.duplicate_id` | Error | 单位 id 重复 |
| `oob.strength_nonpositive` | Error | `strength` 必须 > 0 |
| `oob.strength_extreme` | Warning | 兵力异常大/小，多半写错单位（千人 vs 人） |
| `oob.position_out_of_range` | Error | `position` 指向不存在的省 |
| `oob.starts_in_enemy_land` | Warning | 开局就站在敌方领土里，多半位置写错 |
| `oob.side_without_units` | Error | 某一方没有任何单位 |
| `oob.unit_unreachable` | Warning | 某个单位开局即断补给 |
| `balance.lopsided` | Warning | 可玩方兵力明显少于敌方 |
| `ending.clause_tautology` | Warning | 结局子句恒成立（省略 `value`、或 `ge 0`/`le 0`）——**这条会在第 1 天命中**，几乎一定是写错了 |
| `scale.too_few_provinces` | Warning | `battle`/`siege` 的省数太少 |
| `scale.too_many_provinces` | Warning | `siege` 的省数太多 |
| `scale.missing_positions` | Warning | 小尺度战役却没拆阵地 |
| `domain.land_without_units` | Warning | 声明陆地域却没有地面单位 |
| `domain.naval_without_units` | Error | 声明海军域却没有海军单位 |
| `domain.naval_without_water` | Error | 声明海军域却没有任何水域省 |
| `domain.air_without_units` | Warning | 声明空军域却没有空军单位 |
| `engine.too_old` | Error | 引擎版本低于 `engine.min` |
| `engine.too_new` | Warning | 引擎版本高于 `engine.max` |

## 11 平衡：先跑一局，别只看数字

```powershell
# 每 15 天打一次双方兵力与省数
cargo run -q --release -p sim-testbed -- --module 路径\mymod.imod --ticks 77 --verbose
```

看三件事：

1. **战线动没动**。77 天里地图颜色几乎不变 → AI 卡住了，多半是地形/邻接/姿态写错；
2. **双方还活着没有**。一边归零说明 `effectiveness` 或兵力差得太远；
3. **进攻方推得动但没有碾压**。兵力曲线应该缓慢下滑，不是断崖。

再在游戏里玩一局（`新的战役 → 导入模块…`），确认：地图能读、番号能认、
电报有回应、结局能触发。

## 12 发布前的清单

- [ ] `id` 全局唯一，`engine.min` 填了
- [ ] 每方至少一个 `supply_source`，且从补给源能走到本方所有省
- [ ] 邻接双向、id 从 0 连续
- [ ] 每个省有 `lon` / `lat`（否则地图摆不好）
- [ ] `strength` 单位是千人
- [ ] 双方都有单位，且可玩方兵力 ≥ 敌方
- [ ] 写了 `endings`（至少 3 条不同走向），且都有 `require`
- [ ] `sim-testbed --ticks 天数 --verbose` 跑通，战线在动
- [ ] 游戏里导入一次，能开局、能推进、能出结局
- [ ] 写清"哪些数字是史实、哪些是推断"（用 `note` / 模块文档）

### 发新版：**改 `version` 就够了**

模块会迭代，玩家装过 0.2 之后还要能拿到 0.3。所以「导入」按版本判断，
不需要玩家先手动删掉旧模块：

| 情况 | 引擎行为 |
|---|---|
| 本地没有这个模块 | 装上 |
| 包里的 `version` **比本地新** | 直接覆盖（附 `updated: true` 与 `from → to`） |
| 同版本重装 | 先问一句：重装会覆盖你改过的数据 |
| 包里的版本**更旧** | 先问一句：这是降级，等于退回旧版 |
| 同名目录但 `id` 不一样 | 先问一句：这是两个不同模块撞名了 |

版本号按数字段比较（`0.10.0` **大于** `0.9.0`，不是字符串比）。
装上之后：

- **正在玩的正好是它** → 立刻用新数据重开这一局（否则你会以为更新没生效）
- 否则只是替换文件，下次开始新战役就用新版

**发版前记得改 `version`**——不改的话引擎会认为是"同版本重装"而问你一句，
玩家会以为更新失败。存档不受影响：存档存的是命令流 + 模块 id，
同名模块换了版本还能读，只是回放会用新数据（版本差太大时哈希会对不上，
界面上会明说"哈希不一致"）。

## 14 常见错误速查

| 现象 | 原因 |
|---|---|
| 加载失败，说 `map.asymmetric_neighbor` | 邻接忘了一边。用 `gen.js` 生成就不会犯 |
| 部队全挤在一个省 | 省太少，撞 `STACK_LIMIT`（每方 3 个） |
| 地图上什么也没画 | 省缺 `lon`/`lat` |
| 兵力写成 16000 | 单位是千人，写 `16` |
| 开局就全军断粮 | 没给本方标 `supply_source`，或补给源与本方省份不连通 |
| 敌人突然出现在后方 | 那一带有空省走廊。要么补省，要么留拒止部队——这是玩法问题不是 bug |
| `comms` 里写的延迟没生效 | 键名写错了（只有 `transmission` / `staff` / `order_delay`） |
| 结局永远不触发 | `require` 里的省名写错（必须和 `map.json` 的 `name` 完全一致） |
| 压成 zip 改后缀 `.imod` 后加载不了 | **`.imod` 是目录**，引擎不读压缩包 |
| 将领从不抗命 | `obedience` 全是 1.0，或没写 `persona` / `agenda`（模型没有抓手） |
